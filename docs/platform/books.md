# 书籍订阅

入口为 **订阅 → 书籍订阅**（`/#/subscriptions/8`）。沿用天枢现有导航、登录会话、下载中心和外观；不要求先配置视频账号或视频引擎。订阅概览显示书籍摘要和最近书籍任务。

## 使用

1. 在“书源管理”上传阅读 3 JSON/TXT 规则文件、粘贴单个书源或数组，或者添加返回 JSON 的规则集合直链。集合按天检查，也可以手动更新。上游失败时保留本地规则，远端更新保持用户的启停选择；结构不合格的条目单独报告。
2. 在“聚合搜索”输入书名、作者或 ISBN，按书源分组查询。结果逐步返回，同名同作者合并展示候选来源，本地已整理书籍也参与检索。进入“预览与资料”可以选择来源、浏览目录、读取正文。
3. 在“整理设置”填写天枢进程可见的**绝对目录**，例如 `/media/Books`。NAS 部署时，需要将实际书籍目录挂入现有 Platform 容器，并让运行用户 UID 10001 有读写权限；设置页面本身不会创建宿主机挂载。
4. 选择“订阅并下载”或“仅下载一次”。没有设置目录时，页面先保存这次选择，填写目录后继续。下载中心统一显示章节进度、失败原因、取消、重试和成品下载。追更周期可选每小时、每 6 小时或每天；暂停/停止追更保留已下载内容，当前任务可单独取消。
5. “本地书库”可导入 TXT、Markdown、HTML、EPUB。文本支持 UTF-8、带 BOM 的 UTF-16 和 GB18030；按章节标题拆分。EPUB 保留原始内部资源，并更新书目资料。可以预览、重新整理、下载成品。

规则集合订阅与书籍追更是两件事：前者更新抓取规则，后者检查一本书的目录。

## 元数据与文件

“书籍资料”支持本地成品库、Open Library 和配置的 OPDS/Calibre 书库候选，也可以手动填写。OPDS 支持同源 Basic 认证，密码通过现有媒体密钥加密保存。浏览器只得到是否已保存凭据的状态。OPDS 1 搜索描述及基本 OPDS 2 publication 列表可读。

逐字段勾选保存，保留人工选择。自动补全只在书名、作者明确且唯一匹配时填入缺失的简介、封面、标签和语言；不能确定时不会阻塞下载。人工资料的版本与章节下载进度分开，后台进度更新不使资料编辑无故冲突。已有 EPUB 的资料变化会进入同一队列重新整理，不重新取得已缓存正文。

成品目录：

```text
书籍目录/
  作者/
    书名 [书籍标识前8位]/
      book.epub
      metadata.opf
      source.json
      cover.jpg       # 有封面时
```

已有成品的路径保持稳定；改名或更换默认目录不会自动迁移旧书。EPUB 3 包含目录、正文 XHTML、样式和书目，章节及段落具有稳定标识，便于后续阅读进度/语音定位接入。本次没有接入 Fish Audio、音文强制对齐或向 bot 分享阅读状态。

正文按章节缓存，追更只取得新增或缺失章节。首次缺章可产出明确标注的“部分章节”EPUB；更新失败不会用不完整版本替换已有完整 EPUB。文件先生成、检查、同步，再原子替换；发布意图可恢复“文件已经写好、数据库尚未确认”的中断。目标文件被外部修改时不自动覆盖。取消保留缓存，重试继续补章。

备份应同时包含媒体 SQLite 数据库及其 `.key`、数据库旁的 `.book-content` 目录（导入原件与封面），以及用户指定的书籍目录。仅备份 EPUB 可以保留阅读成品，但不包含订阅、规则、导入原件和恢复状态。

## 引擎与实际兼容范围

复用 [LegadoParser](https://github.com/821938089/LegadoParser/tree/44104b9c513221e08b47ef44e9ac89642b442ee8) 的 Python/JavaScript 规则实现，固定提交、来源摘要和本地适配记录在 `services/platform/media/books/_vendor/SOURCE.json`，原许可证一同保留。不运行上游安装脚本、二进制或浏览器下载器。

已用隔离 HTTP 书站验证 CSS、XPath、JSONPath、基本 JavaScript、中文编码以及搜索→详情→目录→正文链路。解析在独立子进程执行，超时或取消会回收；不同书源最多四路，同一书源的操作串行。HTTP 使用有界请求、证书验证、解析地址固定和重定向凭据隔离；私有地址只在用户配置的 OPDS 书库范围内允许，测试书站通过测试对象显式放行。

不宣称完整兼容阅读 3：WebView、验证码、交互登录、依赖 Android/Java 特有接口的脚本、字形反爬等尚不支持。请求头型规则可以使用导入时携带的头部。规则更新后，正文解析失败且有已验证旧规则时尝试恢复旧规则；未成功验证过正文的书源没有可靠旧版本可回退。

当前处理边界：

- 每次搜索一批 40 个来源，每源首屏最多 200 条；可以继续搜索后面的来源。目录按 100 章展示，完整目录上限 20,000 章，超限明确失败。
- 单个导入文件上限 32 MiB，EPUB 解压资源总量上限 160 MiB；不导入带加密资源的 EPUB。
- 已缓存章节不反复抓取，同一 URL 的上游正文改写暂不自动识别。
- 原生 EPUB 校验覆盖 ZIP/CRC、mimetype、OPF 清单、spine 和 XHTML；没有运行官方 EPUBCheck，也未承诺所有阅读器都已实测。
- 外部书源仓库、真实网站账号及 NAS 镜像尚未验收；yckceo 不可访问不会影响本地规则导入和本地文件整理。

## 开发验证

后端沿用 unittest；新套件为 `tests/backend/test_books.py`。网页联合套件使用真实 Platform 登录、HTTP、SQLite、规则子进程、后台 worker 和文件下载，只有上游书站/账号是合成输入；没有拦截媒体 API 伪造结果。

```text
python -m unittest discover -s tests/backend -p test_books.py -v
npm run typecheck
npm run build
node node_modules/@playwright/test/cli.js test --config apps/web/playwright.books.config.ts
```

浏览器测试需要 `TS012_CONTRACT_DIR` 指向与当前 Platform 固定版本一致的已发布合同目录；Windows 默认使用 `.runtime/venv/Scripts/python.exe`，其他系统使用 `.runtime/venv/bin/python`，可用 `BOOK_TEST_PYTHON` 指定。不要修改合同摘要来绕过不匹配。全部测试写入隔离临时目录，浏览器截图/下载文件在 `.runtime/books-ui/`。
