# 书籍订阅

入口为 **订阅 → 书籍订阅**（`/#/subscriptions/8`）。沿用天枢现有导航、登录会话、下载中心和外观；不要求先配置视频账号或视频引擎。订阅概览显示书籍摘要和最近书籍任务。

## 使用

1. 在“书源管理 → 打开源仓库”直接浏览 [yckceo 源仓库](https://www.yckceo.com/yuedu/shuyuan/index.html)，切换单个书源/合集、搜索、按更新或下载量排序、分页和多选，也可进入详情阅读说明。点击“添加所选并自动更新”后后台获取规则，无需外部复制。默认每天检查，可改为每小时、每 6 小时或每周；订阅列表支持暂停、恢复、手动更新和调整频率。仍支持上传阅读 3 JSON/TXT、粘贴规则或添加 JSON 直链、仓库详情页、`yuedu://booksource/importonline?src=…` 链接。
2. 在“聚合搜索”输入书名、作者或 ISBN，按书源分组查询。结果逐步返回，同名同作者合并展示候选来源，本地已整理书籍也参与检索。进入“预览与资料”可以选择来源、浏览目录、读取正文。
3. 在“整理设置”填写天枢进程可见的**绝对目录**，例如 `/media/Ebooks`。NAS 部署时，需要将实际书籍目录挂入现有 Platform 容器，并让运行用户 UID 10001 有读写权限；设置页面本身不会创建宿主机挂载。成品按“类别 / 作者 / 书名 [标识] / book.epub”整理。类别优先采用书籍资料中的人工选择，其次识别来源标签；无法识别时归入“未分类”。书籍资料可以修改类别。
4. 选择“订阅并下载”或“仅下载一次”。没有设置目录时，页面先保存这次选择，填写目录后继续。下载中心统一显示章节进度、失败原因、取消、重试和成品下载。追更周期可选每小时、每 6 小时或每天；暂停/停止追更保留已下载内容，当前任务可单独取消。
5. “本地书库”可导入 TXT、Markdown、HTML、EPUB。文本支持 UTF-8、带 BOM 的 UTF-16 和 GB18030；按章节标题拆分。EPUB 保留原始内部资源，并更新书目资料。可以预览、重新整理、下载成品。

规则集合订阅与书籍追更是两件事：前者更新抓取规则，后者检查一本书的目录。

修改存档目录或书籍类别后，下一次下载/重新整理使用新位置，已经缓存的章节继续复用。原成品保留，不自动删除；新位置有未知文件时不会覆盖。单纯修改书名或作者保留已确定的书名文件夹，避免自动匹配资料导致频繁改路径。类别同时写入 EPUB 的主题元数据。

## 已验证的规则形式

`webView: true` 没有附带网页脚本时，会尝试普通 HTTP 读取，适用于中华典藏这样的服务端生成搜索结果。仍不启动浏览器、不执行页面脚本；`webJs`、交互登录和依赖浏览器执行的规则继续明确报不支持。Reader 脚本增加 `java.setContent/getElements/getStringList/encodeURI`、来源标识和书籍上下文，网络边界及超时预算沿用原实现，不提供完整 Android/Jsoup 对象 API。

中文路径按 URI 编码请求，已编码路径不重复转义；正文先移除 style/script 等不可读内容，空封面不再误填当前页面网址。

[殆知阁和维基文库标准书源](book-sources/verified-classics.json) 根据各站实际公开接口整理，可直接导入。殆知阁返回整部古籍全文，目录记作一章；维基文库优先读取直接分卷链接，没有分卷时读取当前完整作品页面。长篇、复杂目录及不同网络环境需以实际章节和回执为准，不把首页/节选冒称全本。中华典藏继续通过 yckceo 条目6319订阅，保留上游规则更新。

网文接入可订阅 yckceo 条目7933（速读谷）和7929（得奇小说）；[书海阁公开网页规则](book-sources/verified-webfiction.json) 在条目7948的公开网页规则上补齐站内搜索。2026-10-18 已实读三源《夜无疆》的搜索、完整目录及首/中/末正文；书海阁目录9页、835章，速读谷实测章节正文4页。不同来源目录及更新进度有差异，最终下载量以所选来源的完整目录为准，不跨源自动拼接。

目录及正文翻页共享顺序遍历：保持当前页地址和请求头、去除循环/重复页、忽略停用的JavaScript翻页按钮，正文遇到下一章地址停止。脚本返回null视为空，`java.ajax`继承书源请求头且具体请求选项优先；继承的Cookie/Authorization仅留在原站。任何正文分页为空或请求失败都不会缓存为完整章节。后台检查在下载期间发现目录变化时，先保存当前已取得内容，再立即接着补齐新目录，不等待下个周期。

## 内置源仓库与更新

仓库页面由天枢后端读取，前端使用现有抽屉呈现列表与详情，不受浏览器跨域读取限制，也不会执行原站的广告/脚本。单源列表筛选阅读 3；合集里的非文本资源和不合格规则逐项跳过并报告原因。页面失联可重试，已经保存的书源仍可用；“规则已同步”仅表示规则已获取，实际可用性由搜索/正文预览验证。

每个所选条目保存稳定的原始 JSON 地址，复用现有 `book_feed`、加密 `book_source`、后台扫描和幂等回执，没有另建同步数据库或定时服务。首次添加后通常在下一轮后台扫描（约 10 秒）开始导入；关闭页面不影响后台更新，重启会继续检查到期订阅。重复添加复用已有订阅，保留暂停状态、频率和本地启停；订阅移除后仍保留已导入规则。上游更新失败会保留本地内容并安排重试；部分不合格条目不会抹掉原有规则。

自动更新跟踪所选书源/合集的**同一条目 ID**。作者发布到新 ID 的合集不会自动替换旧订阅，需在仓库重新选择。网站的临时短链不作为内置订阅地址；手动输入其原始批量 JSON 地址仍支持。每次最多选择 100 个条目，合集内每次最多 20,000 个规则；远程集合响应上限 32 MiB，单条规则上限 256 KiB。章节/封面请求仍使用原有 8 MiB 限额。阅读源用空数组或 null 表示空规则时按空对象处理。

## 元数据与文件

“书籍资料”支持本地成品库、Open Library 和配置的 OPDS/Calibre 书库候选，也可以手动填写。OPDS 支持同源 Basic 认证，密码通过现有媒体密钥加密保存。浏览器只得到是否已保存凭据的状态。OPDS 1 搜索描述及基本 OPDS 2 publication 列表可读。

逐字段勾选保存，保留人工选择。自动补全只在书名、作者明确且唯一匹配时填入缺失的简介、封面、标签和语言；不能确定时不会阻塞下载。人工资料的版本与章节下载进度分开，后台进度更新不使资料编辑无故冲突。已有 EPUB 的资料变化会进入同一队列重新整理，不重新取得已缓存正文。

成品目录：

```text
书籍目录/
  类别/
    作者/
      书名 [书籍标识前8位]/
        book.epub
        metadata.opf
        source.json
        cover.jpg       # 有封面时
```

已有成品的书名文件夹保持稳定；更换默认目录或类别后，下一次整理生成新位置的成品并保留旧文件。EPUB 3 包含目录、正文 XHTML、样式和书目，章节及段落具有稳定标识，便于后续阅读进度/语音定位接入。本次没有接入 Fish Audio、音文强制对齐或向 bot 分享阅读状态。

正文按章节缓存，追更只取得新增或缺失章节。网站暂时不可用、限流或规则超时会保留缓存及原有完整 EPUB，按共享任务队列退避后自动续传（最多四次尝试）；不会把这些暂时失败当作已完成的部分书籍。其他缺章可产出明确标注的“部分章节”EPUB；更新失败不会用不完整版本替换已有完整 EPUB。文件先生成、检查、同步，再原子替换；发布意图可恢复“文件已经写好、数据库尚未确认”的中断。目标文件被外部修改时不自动覆盖。取消保留缓存，重试继续补章。

备份应同时包含媒体 SQLite 数据库及其 `.key`、数据库旁的 `.book-content` 目录（导入原件与封面），以及用户指定的书籍目录。仅备份 EPUB 可以保留阅读成品，但不包含订阅、规则、导入原件和恢复状态。

## 引擎与实际兼容范围

复用 [LegadoParser](https://github.com/821938089/LegadoParser/tree/44104b9c513221e08b47ef44e9ac89642b442ee8) 的 Python/JavaScript 规则实现，固定提交、来源摘要和本地适配记录在 `services/platform/media/books/_vendor/SOURCE.json`，原许可证一同保留。不运行上游安装脚本、二进制或浏览器下载器。

已用隔离 HTTP 书站验证 CSS、XPath、JSONPath、基本 JavaScript、中文编码以及搜索→详情→目录→正文链路。解析在独立子进程执行，超时或取消会回收；不同书源最多四路，同一书源的操作串行。HTTP 使用有界请求、证书验证、解析地址固定和重定向凭据隔离；私有地址只在用户配置的 OPDS 书库范围内允许，测试书站通过测试对象显式放行。

支持 Reader3 `concurrentRate` 的毫秒间隔和“次数/毫秒”窗口，语义参考[阅读的并发限制实现](https://github.com/LegadoTeam/legado/blob/master/app/src/main/java/io/legado/app/help/ConcurrentRateLimiter.kt)。分页、脚本追加请求和重定向均计入同源规则预算；请求记录跨规则子进程保留，失败请求也计数。附带书海阁规则设为每 5 秒一次（3 秒实测仍触发限流）；单次规则操作硬超时 60 秒，以容纳该源 9 页目录的间隔等待。长篇首次下载需要相应时间，后续只补新章。

搜索成功不等于正文可读。每本书分别显示“正文待验证、试读取得正文、抽查通过、全目录已保存”及具体失败章节；书源列表的成功仅表示最近请求成功。首次下载前自动抽查开头正文、中间和最新章节，以及已知失败章节；通过后继续下载，已取得的抽查正文直接复用。下载仍逐章、逐分页检查，明确的短登录/付费/验证码/限流提示不入正文，重定向至登录表单会返回登录原因。抽查不是全书可读保证，也不执行网页登录、验证码或付费操作。搜索列表保留未验证结果，优先展示已有正文证据的来源。

## 自动优选与换源补章

订阅扫描与下载沿用同一书籍缓存和任务。系统从已启用书源发现同书候选，先核对原始书名、作者及已知 ISBN，再比对章节编号、标题、顺序和分布于全书的正文；人工修改展示资料不会改变原始匹配身份。正文可读且有可连续对应新章的来源优先，同等进度保持当前首选。仅目录条目更多、宣称更新更快或正文为登录提示的来源不会因此被优选。

已保存正文直接复用；缺章按核验过的来源依次取得，暂时失效的来源退避。完整的上/下或上/中/下分章可以拼成一个逻辑章节，原书籍和已有章节标识、顺序与书库位置保持。新增章节按连续编号接在末尾，明确可对应的中间缺章补到原位置；重复编号、标题冲突、卷内重编号、来源倒序、无法确认作者等情况不会猜测合并。主源无法读取时，只有充足且顺序一致的目录证据才允许备选源加入；可取得原正文时还须比对正文。

订阅和书籍详情显示优选来源、各来源检查结果及已补章数，试读显示实际章节来源；`source.json` 逐章保存来源记录。确认同书的未订阅候选再次订阅会复用原订阅，避免生成第二份相同书籍。完整 EPUB 只有补齐后才原子更新，补章失败保留原完整成品。每轮最多搜索40个尚未匹配的启用源、核验8个同书候选；首次核验需少量其他来源正文，之后同规则的已验证正文及比对位置复用。自动选择不保证源站后续每章可读，也不自动识别上游对已缓存正文的改写。

不宣称完整兼容阅读 3：WebView、验证码、交互登录、依赖 Android/Java 特有接口的脚本、字形反爬等尚不支持。请求头型规则可以使用导入时携带的头部。规则更新后，正文解析失败且有已验证旧规则时尝试恢复旧规则；未成功验证过正文的书源没有可靠旧版本可回退。

当前处理边界：

- 每次搜索一批 40 个来源，每源首屏最多 200 条；可以继续搜索后面的来源。目录按 100 章展示，完整目录上限 20,000 章，超限明确失败。
- 单个导入文件上限 32 MiB，EPUB 解压资源总量上限 160 MiB；不导入带加密资源的 EPUB。
- 已缓存章节不反复抓取，同一 URL 的上游正文改写暂不自动识别。
- 原生 EPUB 校验覆盖 ZIP/CRC、mimetype、OPF 清单、spine 和 XHTML；没有运行官方 EPUBCheck，也未承诺所有阅读器都已实测。
- 仓库列表或规则导入成功不能替代搜索、目录、正文及成品验收。TS189已完成三古籍源的NAS网页/EPUB验收；TS191完成三网文源聚合/试读，以及书海阁《夜无疆》9页目录、835章正式EPUB、真实每小时扫描和隔离833→835章仅补新增验证。速读谷与得奇仍有偶发正文/请求失败，未验证其整本稳定；精确边界见对应任务交接，不将少量通过的来源扩大为整个仓库兼容。yckceo不可访问不会影响已保存规则和本地文件整理。

## 开发验证

后端沿用 unittest，套件为 `tests/backend/test_books.py`、`test_book_warehouse.py` 、`test_book_pagination.py` 和 `test_book_selection.py`。网页联合套件使用真实 Platform 登录、HTTP、SQLite、规则子进程、后台 worker 和文件下载，只有上游书站/仓库/账号是合成输入；没有拦截媒体 API 伪造结果。

```text
python -m unittest discover -s tests/backend -p "test_book*.py" -v
npm run typecheck
npm run build
node node_modules/@playwright/test/cli.js test --config apps/web/playwright.books.config.ts
```

浏览器测试需要 `TS012_CONTRACT_DIR` 指向与当前 Platform 固定版本一致的已发布合同目录；Windows 默认使用 `.runtime/venv/Scripts/python.exe`，其他系统使用 `.runtime/venv/bin/python`，可用 `BOOK_TEST_PYTHON` 指定。不要修改合同摘要来绕过不匹配。全部测试写入隔离临时目录，浏览器截图/下载文件在 `.runtime/books-ui/`。
