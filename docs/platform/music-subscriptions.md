# 音乐订阅、统一曲库与自动下载渠道

入口为 `#/subscriptions/5`，进度与失败重试在现有下载中心 `#/subscriptions/2`。网易云、QQ 音乐、酷狗音乐的账号和歌单统一管理；汽水音乐按用户要求暂时跳过，不依赖用户安装官方客户端。

## 日常使用

在“连接音乐账号”选择平台并扫码。QQ 音乐支持 QQ 或微信扫码。连接后读取本人可访问歌单、选择同步周期并订阅，首次完整同步成功后保存到天枢。账号会话失效时重新扫码；断开账号保留已同步歌单和原音频。

音乐目录使用天枢运行环境中的绝对路径。此部署的 `/media/Music` 对应 NAS 音乐存档 `\\YokiiroNAS\Music\音乐存档`。默认按艺术家／专辑／艺术家 - 歌曲整理，也可按专辑艺术家分组。原位登记不会更改既有文件名或标签。

下载无需配置渠道优先级：

1. 先登记、查找本地曲库，核验有效音频及所需音质。
2. 无论本地是否已有成品，都在全部已登录账号中匹配同版本歌曲并逐首检查最高可下载音质。QQ 或酷狗歌单可以使用网易云账号的下载权限。
3. 统一比较渠道候选和本地成品，选择最高可用音质；同等或更好本地文件直接复用。实际获取后检查完整时长、编码、采样率、位深、大小与摘要。试听或不符合要求的结果会尝试下一个匹配渠道。
4. 写入标签、封面、歌词和来源 JSON，发布一份受管音频。多个歌单按顺序引用这个文件；下载来源与歌单来源分别记录。

会员标记本身不代表每首歌都有下载权限。每次下载前先查询所有已登录账号，逐平台从 Hi-Res 向下检查完整下载权限，再统一比较。默认“最佳可用”；其他期望音质作为最低要求或降级提示，不限制更高音质。多个歌单共用歌曲时合并最低要求，严格要求不被另一歌单覆盖。下载中新增的要求会在当前归档后再次核对。

各候选先以最多1 MiB文件头核对实际编码、位深、采样率和码率；服务器忽略 Range 时也只读取该上限。未知或加密音源仍保留候选，必要时在私有暂存完整校验后比较，不把未知当低音质。所有账号查询完成之前不开始音频传输；最终只归档最高可用结果。任务的 `audio_routing` 保存各平台匹配、权限/失败原因、候选实际音质及最终选择，不保存签名URL。

本地文件参与同一次比较：同等或更高音质直接复用，较低音质有更好可用来源时升级；重复操作会重新检查渠道和少量文件头，但不重复下载完整音频。中断恢复复用已核验暂存，部分发布继续原路径。没有可用渠道但已有符合最低要求的有效本地文件时仍可使用；没有任何成品或获准渠道则保留明确错误，不把试听片段归档。

歌单保留远端顺序、重复成员和不可用条目。远端删歌只更新成员关系，不自动删除歌曲文件。暂停同步不取消已排队下载；取消和重试使用下载中心。M3U8 与 JSON 导出在音乐根 `歌单/<歌单标识摘要>/`；归档、升级和曲库扫描后刷新已关联导出，也可手动导出。JSON 保留完整成员，M3U8 只列出已核验文件。

## 匹配与单份存储

同一平台的稳定歌曲 ID 直接对应来源记录。跨平台需要规范化标题、艺人、完整时长及版本信息吻合，并有一致的 ISRC 或专辑证据；多个同样可信的候选不会被随意选中。现场、翻唱、重混、重制等不凭同名合并。匹配严格时可能漏掉专辑命名不同的同曲，仍保留来源，避免替换成错误版本。

音频完整解码后保存 PCM SHA256，加上采样率与声道作为内容身份；标签、封面变化不会改变这项身份。文件 SHA256 另外用于落盘完整性核验。完全相同音频可以进一步合并来源；不把有损近似指纹当作确定相同的证据。

一个录音身份在当前音乐库中对应一个共用成品。升级音质先验证并发布新成品，更新数据库引用，再清理同一根内精确哈希仍一致的旧受管文件。原位登记的外部原件不被擅自删除。已有软件造成的历史重复副本保留，但后续下载复用选定成品。

Music Tag Web 修改标签后，重新核验音频身份并更新文件哈希，不重复下载；曲库扫描可识别同内容文件改名或移动，更新引用和导出。音频内容实际变化或文件丢失时不冒称可复用。原目录保存设置不直接移动歌曲。

## 本地原件与解码

每小时扫描一次音乐根，也可点击“扫描音乐存档”。FLAC、MP3、M4A、OGG、Opus 原位读取标签及实际音频并登记；符号链接、目录联接和内部控制目录跳过。首次下载前完成初次登记，使已有文件参与复用。

需要解码的原件放在音乐根 `.incoming/`。NCM、QMC、KGM 系列进入现有队列，在私有暂存区通过离线 Unlock Music 工具解码，然后走同一音频核验、标签和发布流程。原件保留，失败可在下载中心重试。相同已处理原件不反复排队。

下载和导入共用自动解锁流程，无需开启开关或配置渠道。根据文件头、尾部标识、下载响应文件名或格式提示识别加密文件；普通音频直接核验，解锁后的 OGG/Vorbis、Opus 也保持原编码写标签和封面。解锁失败会继续尝试其他已经取得下载权限的匹配来源；不会将试听片段或未完整解码的结果归档。

任务中的 `audio_unlock` 和文件回执/来源 JSON 的 `unlock` 记录状态、格式、工具版本、输入 SHA256 和大小。`audio_attempts` 保留失败来源的原因，供数据库查询和任务详情查看；不记录签名 URL 或文件密钥。解锁完成仍须通过实际时长、音质、完整解码及标签前后 PCM 一致校验。相同音频继续共用一个文件、多份有序歌单。

解码能力以文件版本为准：QMC STag/MusicEx 需要外部密钥、KGM v5/KGG 需要客户端数据库时，显示“需要客户端密钥”；未知加密版本与损坏输入分别报错，保留原件。归档编码支持 FLAC、MP3、M4A（AAC/ALAC）、OGG（Vorbis）及 Opus，不保证所有后缀的文件都可解码。NCM、QMC 使用合成音频经过真实工具及归档流程验证；没有使用用户商业音乐加密原件验证全部版本。会员下载权限与文件解锁能力分别检查。

## 实现归属

继续使用 `<database_path>.media.sqlite` 的 Repository/schema 2、共用 jobs/租约/取消重试/Retention。没有第二个音乐数据库、外置 API 服务或下载守护进程。

| 文档                                                 | 用途                                   |
| ---------------------------------------------------- | -------------------------------------- |
| music_account                                        | 平台主体、状态及 AES-GCM 加密会话      |
| music_playlist / music_track                         | 按账号隔离的有序歌单及来源资料         |
| music_recording / music_source                       | 统一录音身份、跨平台来源绑定与匹配方法 |
| music_match_index / music_source_index               | 按元数据查找录音、按录音查找来源       |
| music_library_file / music_content_index             | 共用成品及解码音频身份                 |
| music_request / music_playlist_jobs                  | 各歌单需求及共享任务关系               |
| music_publication / music_stage / music_retired_file | 原子发布、暂存与升级恢复清理           |
| music_file_observation / music_import_scan           | 文件变化及索引扫描进度                 |

账号密钥沿用媒体 `.key`，备份需要同时包含媒体数据库与原密钥。公开页面和来源 JSON 不包含会话、密文或临时下载 URL。歌曲身份与账号下载凭据分别保存；复用本地成品无需再次取得原下载账号会话。

网易云保持现有 Python HTTPS 接口，并增加歌曲搜索。QQ/酷狗由固定版本本地 `tianshu-musicbridge` 通过 stdin/stdout JSON 处理单次请求；Cookie 不出现在命令行或日志中。解码工具 `tianshu-musicdecode` 禁止网络。依赖、许可证和对应源码说明见 [musicbridge](../../tools/musicbridge/README.md)、[musicdecode](../../tools/musicdecode/README.md)。Docker 构建从固定 Go 工具链及 go.sum 构建静态工具，并包含对应源码包。

下载 CDN 单独使用空 Cookie jar，逐跳检查所属平台域名。单音频上限 1 GiB，同时受现有 engine.max_bytes 限制。保持原编码；不通过转码伪造无损。发布继续使用现有目录锁、safe_path、fsync 和不覆盖硬链接安装。

## 同源接口

所有操作为 `POST /api/web/media/music/<operation>`，复用控制台会话、Origin、CSRF 和幂等回执；不新增权限层。

| operation                                            | 输入与用途                                                               |
| ---------------------------------------------------- | ------------------------------------------------------------------------ |
| view                                                 | 账号、歌单、设置、平台可用能力、automatic 选路及扫描状态                 |
| accounts/qr/start                                    | provider，QQ 可带 login_type=qq/wx；空对象兼容网易云                     |
| accounts/qr/poll                                     | qr_id，仅同控制台会话可使用                                              |
| accounts/revoke                                      | account_id、expected_revision、client_id                                 |
| playlists/list / subscribe / scan / detail / control | 沿用完整快照、分页、周期及暂停接口                                       |
| playlists/downloads / download / export              | 歌单音质与自动下载、立即排队、导出                                       |
| settings/save / inspect                              | 音乐根与布局、目录样本                                                   |
| library/view                                         | offset，每页最多 100 个录音及当前共用文件                                |
| library/scan                                         | 空对象；幂等排入一次曲库扫描                                             |
| library/link                                         | source_key、recording_id、expected_revision、client_id；显式纠正来源绑定 |

## 验证边界

已有部署的网易云本人账号与 SVIP 下载链路已实测：8 首无损归档、4 歌单导出、SMB 48 文件摘要一致。此事实属于 TS-151 既有部署。

TS-154 新增的跨平台选路、原件登记、NCM 解码、单份归档及页面在隔离测试中验证；QQ/微信/酷狗真实二维码生成及等待扫码已验证，尚未取得用户这些平台的登录和私密歌单联验。汽水按用户选择跳过。自动解锁接入记录见 [TS-156 交接](../handoffs/TS-156.md)，之前统一曲库记录见 [TS-154 交接](../handoffs/TS-154.md)。精确发布状态由协调仓库记录。
