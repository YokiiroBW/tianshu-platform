# 视频订阅与下载网页

主导航“个人空间 → 订阅”的入口为 `/#/subscriptions`，默认概览，`/4` 也可直接进入概览。稳定子页 `/0`、`/1`、`/2`、`/3` 分别为视频订阅、链接下载、下载中心、账号与媒体库，刷新和返回保留当前子页。旧 `/#/resources/2` 书签替换为 `/#/subscriptions/0`，保留原订阅管理目的地；任务中心的媒体来源直接进入下载中心。订阅激活时在原主导航下展开带图标的五项竖向子导航，手机在导航抽屉中访问；不显示顶部横向子导航和壳大标题，保留面包屑及可访问的子页标题。复用统一登录、设计令牌和 `StatusRail`；媒体页面独立懒加载。媒体事实来自 `POST /api/web/media/*`，浏览器不存账号会话、规则执行结果或权威队列。

概览的四项任务指标直接读取 `view.overview.jobs` 的全量服务端统计：“已完成”为 published/completed，处理中为下载、校验和发布阶段，等待队列包含重试等待，需要处理包含失败、未知、重新登录和补全元数据。累计任务包含已取消任务，四项指标不冒称累计总数。旧后端缺少 overview 或返回 null 时显示总量不可用，不从 view 中最多 100 条近期任务推算总量。订阅环图统计完整 subscriptions 数组，近期任务仅显示本次快照最近五项。

暂存磁盘读取 `overview.storage`，说明容量包含同盘其他文件，不作为 Emby/Jellyfin 媒体库容量。不可用或字段不完整时不显示零容量。引擎、账号和目标展示当前读取的状态；发布目标“配置可用”不宣称服务器在线或已入库。空列表、未配置和故障状态保持紧凑，故障后的历史快照明确标注陈旧。全部快捷入口复用已有业务页面。

订阅管理可按名称、来源 ID/类型、账号、目标媒体库查找，并按运行、暂停、登录、规则和初始化状态筛选。状态汇总只统计当前成功读取的订阅记录，不随列表筛选改变。卡片保留最后成功扫描、下次安排、扫描间隔、成员基线和操作；未建立基线、暂停或待处理时说明后续动作。

## 使用流程

- 链接下载：输入 B 站视频或短链接后解析，选择分 P、所有选中分 P 均可取得的画质以及已登记媒体库，再创建下载任务。预览过期需重新解析；未明确允许降级时不降级。一个投稿内选中的多个分 P 由同一个任务发布。
- 订阅：账号与四类来源 → 历史或仅后续新增 → 规则/质量 → 目标库及预览。来源以直接粘贴收藏夹、UP 主投稿、合集或系列链接为主，也接受 ID；后端规范化后展示来源标识。首次完整成员基线与视频发布时间分别处理；未完成基线不显示订阅已初始化。暂停订阅保留已入队任务；立即扫描与显式历史重算分开。
- 规则：字段与操作沿用 TS098，组内 AND、组间 OR，黑名单优先。试算显示决定、原因和完整规则解释；规则错误阻止继续保存自动配置。规则判定只在后端执行。
- 下载任务：`jobs/list` 每页 20 条，按状态筛选并通过服务端游标加载完整历史；初始 view 的 100 条不作为历史上限。切筛选清空旧游标和列表，取消并拒绝迟到续页。显示实际阶段、画质和可操作动作；后台的 0..1 进度换算为百分比，未知进度不造总量。详情分开展示资产发布回执与每个 Emby/Jellyfin 核对结果。补元数据和重新解析来源带 `expected_revision`；冲突保留未保存输入，重新读取可放弃输入并取当前值。原因优先显示中文，原码在折叠诊断中；标准 B 站质量编号转换为 1080P、720P 等标签。
- 账号与媒体库：真实 B 站授权 URL 在本地通过 `qrcode-generator` 生成二维码；扫码状态可见时检查、隐藏后暂停。本人 Cookie 导入后立即清空输入，不写本地存储。目标库及服务器只读服务器登记，不接任意目标路径。

## 请求与恢复

共享网页登录使用 Cookie、CSRF 和同源 `webFetch`。每个读取槽位具有独立取消器，切账号/来源/规则或关闭详情立即作废旧结果。退出登录和会话失效会卸载页面、清空预览与详情。传输失败保留已读取快照并标注陈旧；恢复后重新读取事实。

作业后台生命周期与页面分离。离开页面只取消等待；真正取消作业需要 `jobs/control`。未确认的同一写请求在当前页面保留 UUID 幂等键和用于准确比较的临时参数，重复操作沿用原键，成功后才释放；当前会话结束或页面卸载即清理，不写浏览器持久存储。UUID 复用现有 `requestId`，支持 LAN HTTP。

页面状态轮询为 15 秒，一个在途读取；故障按 30/60/120 秒退避，隐藏及卸载取消，恢复可见后立即重读。扫码检查独立为 5 秒，读取失败改为 15 秒，达到二维码寿命即停止。开发模式 StrictMode 的每次 setup 都重新激活，cleanup 不设置永久关闭状态。

同一二维码的 waiting/scanned 变化不会重启轮询；恢复可见时保留5秒最小检查间隔。任务详情的“媒体组织”来自 Job.layout。订阅从1P即使用稳定分P剧集布局；已有手动单视频成品若需要改为订阅布局，后台明确返回布局冲突，页面提示选择独立媒体库。

宽屏采用列表/360px 详情双栏，中屏详情置于列表上方，手机详情替换列表并提供返回与焦点恢复。子页导航沿用应用壳的原生链接，支持 Tab 与 Enter；任务详情支持 Escape。遵守既有减少动态偏好，无持续背景动画。

任务中心只消费媒体作业投影，保留统一五档状态和具体媒体阶段，详情跳转责任页面进行取消与重试；不建立第二份作业。

## 验证入口

先在依赖齐全的检出执行 `npm run typecheck` 和 `npm run build`。本地无 npm shim 时等价执行：

```powershell
node node_modules/typescript/bin/tsc -p apps/web/tsconfig.json --noEmit
node node_modules/vite/bin/vite.js build --config apps/web/vite.config.ts
node node_modules/@playwright/test/cli.js test --config apps/web/playwright.media.config.ts
node node_modules/@playwright/test/cli.js test --config apps/web/playwright.media-dev.config.ts
```

`media.spec.ts` 明确使用合成 API 替身，覆盖三尺寸、实际画质/分 P、四来源、规则错误、扫描/暂停、二维码/导入及检查间隔、元数据版本冲突、取消/重试、晚到响应、退出与离线、幂等重放及键盘。`subscriptions-navigation.spec.ts` 覆盖竖向主导航、旧书签与登录回跳、五个子页刷新/返回、查找与状态筛选、状态汇总范围、空列表/无匹配、账号恢复入口和任务中心直达。`subscriptions-dashboard.spec.ts` 覆盖全量统计与近期列表区别、零与未知、磁盘不可用、错误及陈旧快照、快捷入口、紧凑未配置、三尺寸浅/暗色及可访问性。实际平台 HTTP 联验使用 `playwright.media-joint.config.ts`，需先由 backend 所有者启动隔离 `run_media_fixture.py`，设置 `MEDIA_JOINT_URL` 和输出的 `MEDIA_FIXTURE_CONTROL` 再执行。请求不被前端替身拦截；新增概览用例直接比较服务端统计与 KPI、累计和取消数量、近期范围及真实暂存磁盘显示。该套件会控制隔离上游，不适用于生产。实际结果及边界见本次前端交接。

本次未推送、部署 NAS 或使用真实 B 站账号。沿用已有依赖，无新增依赖或锁文件修改。
