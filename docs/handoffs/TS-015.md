## 完成行为

- 唯一 `Models` owner 增加原生 `openai-responses` 配置生产者：独立 `native_configs` 表、独立严格递增 `native_config_version`、独立撤销键空间与不可变内容摘要。同版同摘要幂等，同版不同内容或迟到旧版 409，撤销版本不可重发（403）。
- 原生授权只读显式 `caller.native_config_versions`；缺省为空集，绝不继承 `config_versions`。指定版本必须在授权集内（否则 403）、存在（404）、未撤销（403）、未过期（503）；`null` 只在授权集内、未撤销且当前有效的快照中取最大值，无可用快照失败（503），不先读全局最高版本。撤销 8 后 latest 回落到 7。
- provider 注册按协议钉、精确 base_url、credential_ref、credential_namespace、模型、已验证能力与已审地址逐项绑定；原生要求登记项显式 `openai-responses`，旧 Chat 只接受未钉协议或 `openai-chat-completions` 的登记项。发布时在同一写事务内校验 schema、唯一 provider/workload、binding 模型一致、有效期（默认≤1h、最多 24h）与文档不含任何已登记环境凭据。
- 端口 `POST /internal/v1/model-config/native/snapshot` 复用服务认证 `config.snapshot` 与已签发来源（receiver `platform`、purpose `config.snapshot`），默认关闭，设置 `native_config_http: true` 才注册。默认关闭时返回不透露存在性的 404。错误一律 `model#error`（`contract`、`retryable=false`、每码一个合同状态）；旧 Chat 路径与 `common#error`、撤销/到期 410 完全不变。
- CLI 新增 `publish-native`、`revoke-native`、`view-native`，复用既有 operator 权限 `config.publish`/`config.revoke`/`config.view`，不新增写服务、网页入口或浏览器密钥通道。`view-native` 只输出版本、有效期、availability 与 provider/model/协议/验证状态。
- 本地 SQLite schema 提升到 2：版本 1 旧库迁移前生成唯一 `<db>.pre-native-<hex>.sqlite` 备份（含 WAL），在单个 `BEGIN IMMEDIATE` 事务内建表；版本 0 演练旧库仍走原 `.pre-source-` 备份，不额外产生 native 备份。
- 范围仅 `services/`、`tests/backend/`、`docs/`、`AGENTS.md`、`README.md`：未改 `apps/web`、依赖锁、已发布合同或网关工作树。
