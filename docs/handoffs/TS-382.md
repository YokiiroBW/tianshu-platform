已发现会话仍调用原 `bot-observation/discovered`，保留原机器人管理解锁和 read_enabled 限制，读取预算 500 条 intake 元数据，未覆盖明确提示；图不会绕过原发现记录权限。默认策略不伪造实际会话。私聊名单仅表示回复范围，角色始终按账号默认继承，逐会话是否允许回复复用原 `decision`。群角色保存直接使用原 `bot-observation/policy`：重新读取当前 revision，保留其余群规则、关键词和私聊策略，沿用原权限、版本和回执语义，没有新写接口或新解锁门禁。

运行图只读冻结 12 字段日志，使用真实 correlation、实例、sequence、event、outcome、duration、error_code。列表把明确业务阶段关联优先，并可筛选全部 / 明确业务阶段 / 服务观测。详情保留该关联全部实际事件，按服务分泳道；阶段间虚线只作阅读方向，不表示父子调用或执行顺序。普通 HTTP / peer 成功不推定记忆、模型、投递或业务完成。耗时只显示事件自身记录值。没有 reader、查询失败、空结果、截断和未观测分别展示；不每秒全量轮询，默认手动刷新，可选每 15 秒刷新列表且隐藏时暂停新请求。

明确阶段映射复用现有 / 本批责任方登记事件：

- Companion `turn.prepared/queued/generation.*/cancelled`：陪伴包络；generation 不是单次模型请求。
- Companion `turn.memory.*`、`turn.knowledge.*`：实际记忆 / 资料读取边界。
- Gateway `upstream.call_started/first_output/call_finished`：模型尝试；首块不等于结束。`receipt.persist_failed` 只提供失败回执证据。
- Companion `turn.delivery.*`：回复投递；`memory.phase.*` / `outbox.flush`：异步处理，不能单独证明全部记忆落库。
- Companion `proactive.delivery.*`：主动投递阶段，不证明生活产物已生成；`proactive.reconcile.*`：实际回执恢复。

## 宿主装配接口

`WebConsole` 已构造 `console.flow_graph = WebFlowGraph(console)`；统一宿主只需注入：

```python
console.flow_graph.event_reader = reader

# async reader(*, correlation_id: str | None, start_ns: int, end_ns: int, limit: int)
# -> {"events": [frozen_safe_event], "complete": bool}
```

reader 持有既有 guard 只读凭据、CA、固定五来源选择器、查询限额与关闭 / drain；P 不导入根部署实现、不接收任意 LogQL，也不暴露 URL、token、origin_ref、正文或 payload。correlation 只接受 32 位小写 hex。P 再次验证冻结字段、UUID、时间窗、有限耗时及服务范围，同事件身份重复一致时去重，冲突或 reader 异常仅返回固定 `flow_query_unavailable`。原实例缺 reader 时明确 `not_configured`，不假装读取成功。

同源 POST：`/api/web/flow-graph/relationships {}`、`traces {minutes:5|15|60}`、`trace {correlation_id,start_ns,end_ns}`。纳秒边界在浏览器用十进制字符串，详情最多 1 小时时间窗、1000 条事件；索引最多 1500 条 / 30 个关联。完整性由 reader 证据与 P 截断共同决定。沿用 Cookie / CSRF / Origin，读取前后核验会话与原 `bot.manage` 权限；没有新增实际授权。
