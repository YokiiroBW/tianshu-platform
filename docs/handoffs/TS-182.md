## 产品与验证入口

产品修复固定于 `d3f23ee00d7e3dab3c2f5114add98e679de0fc3f`，父提交 `9ea5e6779db2a13645c210abb26609b82ff5ab04`，两者均须保留。只改 `services/platform/infrastructure/{client,process,supervisor}.py` 和对应 Linux 用例，没有音乐、共享入口、清单/锁、合同或权限修改。平台仍按 200 个 ID 顺序请求，保留 90 秒全轮上限；NAS 部署使用已有合法 `timeout_ms:30000`。

实际缺陷是 Linux 执行器内的 SSH 使用独立 session，平台仅杀执行器进程组时不能回收 SSH。每次调用现由短生命周期 supervisor 在 fork 前设置 child subreaper 和 PDEATHSIG，前后核对平台父 PID；执行器正常 stdout/stderr 和退出码直接透传。取消、执行器先退出或平台父突然退出时，supervisor 从 `/proc/<pid>/stat` 的 PPid 识别当前直系孩子，持续 SIGKILL + wait 直到 ECHILD。收养后的独立 session 同样回收；单线程所有者尚未 wait 的孩子 PID 不会被重用。平台不在清理完成前杀该收养者。Windows 已验收的挂起启动/Job 路径不变，不把整个平台设置成 subreaper，也不改变节点 SSH 严格身份配置。

新增入口与部署条件详见 [节点与容器观测](../platform/infrastructure.md)：

- `tests/backend/verify_infrastructure_deployment.py`：显式公共 origin、既有账号环境/文件引用，真实 Cookie/CSRF；全量分页、201 后的尾部指标、连续差值、Compose、限定日志及重启后两次后台推进；脱敏回执。
