## 变更与复用

- 扩展原 `media/rules`：发布时间、收藏时间、分 P 数量、全部分 P 总时长、联合投稿；类型化 `equals/not_equals/gt/gte/lt/lte/between`，可选 `negate`，包含边界的范围，带时区时间比较。旧文本、黑白名单/AND/OR、正则子进程和政策摘要保留；默认/显式 `negate=false` 有同一个摘要。
- `rule_context.py` 是来源事实投影的共同入口，试算和订阅扫描共用。缺失返回 `not_matched/field_missing`，NOT 和 `not_equals` 不反转未知。零秒和布尔 false 正常参与比较；有分 P 时长缺失就不算部分总和。
- `Bilibili.scan` / `scan_watch_later` 返回 `dict[bvid, RuleSourceContext]`。收藏时间严格来自所选 FID 的实际 `fav_time`；其余来源和无效时间保留未知。完整分页/计数/重复/预算校验及 watch_later 账号语义保留；原基线事务仍接收 BV 集合，失败不覆盖基线。不做收藏移除删片。
- `view` 的 `staff` 事实置于 connector 私有 `rule_context`，不向已发布 metadata/NFO schema 塞字段。
- `rules/preview` 原请求仍有效，新增互斥 `source` / `subscription_id`。服务器扫描来源、取服务器登记账号，订阅和预览账号不同拒绝；扫描前后复核账号、返回前复核会话。顶层 `context` 提供五个字段的可用值和成员状态。每条 trace 新增 `negate`。
- 含高级字段时 `snapshot_revision` 包含快照与真实来源上下文，任务 `rule_evidence.context` 保存可复核事实；旧纯文本仍用原快照摘要。没有 config/engine/cache/retention/repository、网页、manifest/runtime 或 contracts 修改。

精确词汇、请求/响应和摘要公式见 [高级规则说明](../platform/media-advanced-rules.md)，已向父级及 TS-150 前端同步冻结合同。
