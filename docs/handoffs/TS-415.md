# TS-415 Gateway 完整分块响应读取

基线 `a35eb0d165584d67d3402bce87fd36ba84d6f557`；分支 `codex/ts415-provider-response-20261029`。

## 修改及影响

ProviderManagement.gateway_request 原用 StreamReader.read(1048577)，正数 read 只保证至多读取这些字节，不保证等待完整响应。Gateway 将大型向量 JSON 分多次返回时，第一次 fragment 就进入 JSON parser，合法响应被误报 upstream_invalid。

改为已有 aiohttp/单容器 client 均支持的 iter_chunked(65536)，逐块累计到 EOF，并每块检查既有 1 MiB 上限。保持 20 秒 total timeout、固定 Gateway endpoint、鉴权、无重试及错误码/向量解析合同不变，无新依赖。

MemoryRetrieval.execute（services/platform/memory_retrieval.py:297）确实直接调用同一个 gateway_request；provider test、模型列表、embed/rerank 均从此边界读取。此次没有修改它们的解析、配置或 owner 行为。
