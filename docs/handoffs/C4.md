## 最终行为与复用位置

- `bot_delivery.py` 在原 `.bots.sqlite` 的 replies 队列实现正式 v2 append/query/finalize/cancel/context，普通回复、Direct、主动共用 claim/真实 ACK。expression 表只记录追加/闭合与所有权，不另建发送账本。取消未领段；已领段保留 unknown 与后到 ACK，不声称未执行。沿原 BOT 注册 entry、账号、渠道、actor 和实际 QQ 策略校验。
- 同段媒体必须有真实 bytes、匹配引用/type/SHA。32 MiB decoded、最多四项按同 expression 累计，append 重放不重复计；文本段仍独立限额。只有该可信发送入口放大到 45 MiB JSON，常规请求仍 1 MiB。文本/作品引用不冒称附件，图像/音视频缺物化拒绝。web 也使用原 replies 队列，原 v1 仍为真实既有消费者保留，不回退另一个队列。
- `web_life_management.py`、`web_content.py`、`web_people_life.py` 是薄权限/传输适配：生活、活动、情绪、作品由 Companion；上传、正文、原件、版本及 access 由独立 Knowledge。Platform 不复制可写正文库。首次生活访问/上传经 Core 原 conversation owner ensure，只确认它与 Memory 回传的真实 scope，不造 input/turn、不开模型。
- RoleRuntime 从原耐久角色 intent 重建稳定 operator/source entry；life-only 不进入聊天投影，也不授 dialogue。新增可选 Knowledge peer：启用前同步 Knowledge 自有 RoleGrants，停用/取消时同步 false；重启补入旧 active/disabled 角色，并保留 disabled。沿既有 Memory/Companion CAS、重试账本，不共享产品数据库。
- 管理 image_backend 与 current chapter 先核既有 role.manage/life.read，再用 manager caller；正文仍走真实 scope。QQ 人物页沿 qq.admin.view/manage 只读主动开关、投递元数据，不借 QQ 作者 origin 读私有正文；明确返回 scope_required，不伪造空数据。
- `memory_proofs.py` 绑定本次真实 physical source/author/revision、完整 operation digest、账号及 scope；C3 解释自然语言，Memory 唯一裁决目标/版本/合法写入。无关键词裁判、第二次模型调用、网页确认。digest 严格只删顶层 query/command/proof_ref，保留 null、文字和数组顺序，sorted-key UTF-8 JSON SHA256。
- `web_memory_links.py` 使用两个真实作者：源网页登录开始，目标通过已认证私聊输入回复一次性句子，签同一具体 association 摘要，Memory 返回 linked 后才呈成功。支持 CAS revoke；pending status 在当前 owned/scope 校验后恢复同一确认句，未缓存权限，也不生成另一挑战。
- `service_credentials.py` 复用 ExternalCatalog AES-GCM/HMAC/CAS 存 `images:<actor>`；浏览器只看 configured 状态。Companion 专用 resolve 必须匹配 purpose=companion.images、credential_ref、已启用 backend origin；不公开 catalog/token，不给模型任意凭据或 grant 工具。
- provider 目录仅当前同 revision 文字测试标 text verified，其余 native 能力为 unverified、允许尝试。保留 OpenCode Zen/Go、会话修复及 QQ/登录/天气原入口。

## 最小生产配置差异（无秘密值）

复用原服务身份、token role、CA、QQ连接/策略/账号，不重建目录或配置系统。URLs 均为既有内部服务地址，填本部署值；不得把下面的逻辑身份名当额外用户权限。

1. Platform `role_runtime.memory` 保持原 Memory；增加 `role_runtime.knowledge:{base_url,token_env,ca_file?,timeout_seconds?}` 指 **独立 Knowledge** 自有 RoleGrants。`web_knowledge:{enabled:true,base_url,token_env,ca_file?,projects:[原项目注册...]}` 也指 Knowledge；项目注册维持现有旧 /execute 功能，不是新正文 owner。不能把 memory URL 代替。
2. Knowledge 正式 `knowledge_cli --config <knowledge> serve --client <原客户端> --port ...`（依赖固定097ccfa）。保留 knowledge.clients/projects；自身 database_path/content staging/source_sync.recovery_path 和 role_grants_database_path 均为 Knowledge 自有持久路径，不复制 Memory people/accounts。`callers.platform` 需 `role_admin:true` 同步角色；内容权限独立显式列 `content_uploads/content_upload_status/content_acquire/content_read/content_original/content_access`、`allow_runtime_roles:true`。网页 user caller 配置现 Platform issuer URL `/internal/v1/origins/resolve`、专用 resolver token/CA、`issuer:platform`。actor Companion caller 配 `runtime_content:true`、`allow_runtime_roles:true` 和 `content_acquire/content_read/content_original`（无需 access/grant 权）。原 token 可按实际已有调用身份复用，role_admin 不隐式授内容。
3. Core `services.knowledge:{url,token_env,ca_file?}` 明确指独立 Knowledge，仅 content acquire/read/original 使用；identity/context/source-sync/propose 仍 `services.memory`。`services.platform` 既有 Companion principal 的 source.input 覆盖 proof.issue 与窄 image credentials。`services.platform_sender` 使用原 Companion dialogue.send 身份，现 `/internal/v2/bot-delivery/*`，无需新 recipient proof/数据库。原 sender grant/token 保留。
4. Memory `memory_context_proofs:{url:<Platform>/internal/v1/memory-context/proof/verify,token,ca_file?}`，使用现 Memory→Platform source.current 服务凭据。Memory Companion caller 显式加 `context_query/context_propose/context_receipt/context_batch/context_association` 与当前 role grants；网页 association caller 指实际 Platform issuer/context_association、allow_runtime_roles，角色管理 caller 仍 role_admin。Platform proof.issue 只 Companion/source.input，verify 只 Memory/source.current，不向浏览器暴露 token。
5. 真实 operator actor entry routes 需现有 Platform→Companion/dialogue、Companion→Memory/dialogue、Companion→Platform/dialogue；Knowledge 网页 user issuer 另复用 **Platform→Memory/dialogue** 的实际注册路由。配置它后 RoleRuntime 稳定派生入口会重建同路由。Core 保留既有 platform/web binding；新增角色由原 RoleRuntime 写入 actor_ids，life-only capabilities=[] 保持不授 dialogue。首次 ensure 不新增入站或并行身份表。
6. Core 保留现 `life_readers` reader credential/grant/runtime_roles。管理服务 `platform` 如需读 image_backend/current章节，需其本身 reader grant：`{reader_id:<与web-life不同的真实ID>,actor_ids:[原授权],runtime_roles:true}`，不能两个 caller 共用 reader_id；manager 仍核 role.manage 和原精确 scope，不扩任意 QQ 私域。独立 reader 可复用 Core 已显式 platform issuer resolver，reader token/grant先核。
7. 图像：Platform 保留现 `web_external.directory` 加密 key/catalog；UI 保存真实 backend origin/profile standard_sd/checkpoint/enabled 与可选密钥。Core `services.image_credentials` 可显式指 Platform，未设复用现 services.platform；解析路径 `/internal/v1/service-credentials/resolve`、purpose companion.images、audience 精确 backend origin。无需设置原件永久 URL、不安装未获地址的图像服务。
8. Gateway 本轮消费者是已有 **`/v1/chat/completions`** 的完整 messages/tools/image_url/SSE，沿原 ChatClientGrant/provider/config version/OpenCode session。`max_request_bytes` 改为 **4 MiB** 对齐 1.5 MiB decoded vision+base64预算；没有 `/v1/responses` 消费者，不必启用 native_enabled/native_clients 或造另一 config/version。前置反代若有独立 body limit，需容纳原上传32 MiB和媒体JSON45 MiB；产品自身仅相应已认证路由放大。
