## 变更

- `bot_connections` 只接受预登记的插件槽位、精确会话和作者 Sources entry；服务端的受限 platform principal 负责 `register_input` 与 `dispatch`。每连接随机 Bearer 只存摘要；默认停用，停用拒新事件和领取，轮换令旧令牌立即失效。
- 新建 `<database_path>.bots.sqlite` schema 1，保存连接、事件去重意图和回复台账。入站事件先落 unknown 意图，后请求 Core admission；回执 unknown 不自动重放。回复经现有 `/internal/v1/conversation/send` 收件、插件 claim、原 SDK ACK、Core `reply-status` 查询；只有 SDK 给出实际消息 ID 才记录 sent。一次领取后不再分发第二次；超时或停用保守记 unknown，同 attempt 的晚到 ACK 可补全事实。
- 同一实际 bot self ID、渠道、外部会话、线程及角色仅一个启用 reply owner；不同 Core binding 或插件宿主无法绕过。不同实际机器人可显式共存。`/api/web/bots/*` 走既有 Cookie/CSRF/Origin 会话，写操作需要管理员密码短时解锁及 `bot.manage` action。设置页展示预登记槽位、连接状态、最近事件、台账计数、一次性令牌及停用/轮换操作。
- sidecar 纳入可选运行健康检查。部署说明与两插件合成设置片段位于 `docs/platform/`。

## 验收整改

- 针对总控评审 `64acb76:docs/reviews/BOT-R-2026-09-28.md` 的 P1，连接判重改为 `(namespace, self_id, channel_conversation_id, thread_id, actor_id)`，忽略 Core binding 和宿主类型。冲突连接无法启用；若旧台账已有两个启用连接，其新事件、领取和回复入队也会拒绝。回归以不同 binding 的同一真实机器人验证仅一次 Core dispatch。
- 针对 P2，`Bots.event` 的入站 SQLite intent 事务和完成结算分别经有界 `LocalWork` 执行，二者之间保持异步 Core dispatch；测试持有 sidecar 写锁 450 ms，确认无关事件循环定时器仍按时运行。修复前两条新回归均实际失败，修复后通过。
