## 实现与复用

- 原 BotObservation pump 保留唯一轮询入口；server 使用 `wait=False`，既有独立调用默认 `wait=True` 等待同一个批。每账号最多一个 20 事件在途批；忙时重复 poll 只续真实 SDK 租约，不缓存第二批、派发或提前 ack。继续使用原 SDK 持久队列及 source/delivery 幂等账本。
- 业务仍按 record → Companion 接受 → 当前策略锁内回复准入 → ack 顺序执行；权限收紧、版本核验和来源检查保留。原账号上限 64、SDK 30 秒租约和公共协议保持。
- 回复扫描改为每次八个 scope 的有序轮转页；批内原有交错投递调用复用该页，不再重复全目录扫描。SQL、配置读取和完整本地操作复用 LocalWork；内存 auth/source/slot 投影仍在事件循环同步安装。
- server 原生命周期内分离 legacy adapter/alias 与观察轮询循环，legacy 明确跳过 observation 配置。关闭先取消并收回循环、批任务和本号 LocalWork await；不等待其他所有者的全局线程池。已开始 SDK 发送被取消时只按原账本结算 unknown，不重发或误报 sent。

未新增队列、心跳服务、协议、配置开关、依赖或取消框架。改动限两个运行文件及相关后端测试。
