# TS-017 交付记录：家庭设备状态与受限控制

## 目标与范围

按 V2 §8/§10、U60/U98、A10 接入 Home Assistant 连接器与网页家庭设备页：登记实体的
当前/过期/离线状态与采样时间、显式授权的 light/switch 开关动作、sensor 只读；服务器登记
地址、实体与动作模板，浏览器不传凭据或任意目标。仅使用官方 REST 的状态读取与服务调用，
不写 `states` 冒充控制；受理回执与后续观测分开显示，unknown 不自动重发。不支持门锁、门、
报警、场景与脚本。仅隔离合成验证，未接触真实 HA 实例、账号或设备。

## 实际变更

### 后端（services/platform）

- 新增 `services/platform/home.py`：可用顶层设置 `home` 的登记与启动校验、持久读数、同源
  `/api/web/home/{view,refresh,unlock,lock,control}` 分派，以及 HA REST 客户端。
  - 读数：`refresh` 对每个登记实体做一次有界 `GET /api/states/<entity_id>`；`availability`
    区分 `current`/`stale`/`offline`/`unavailable`/`unknown`/`never_read`，保存 `observed_at`
    与 `attempt_at`，并在读数真的变化时前进 `revision`。HA 的 `unavailable`/`unknown` 与
    无法解释的状态一律保持 `null`，不换算成关闭或零；失败读取保留上次读数并标注离线。
  - 控制：`POST /api/web/home/control` 只接受 `{template_id, expected_revision, client_id}`；
    实体、域与服务全部由服务器从登记表解析，只调用 `/api/services/<实体域>/<turn_on|turn_off>`。
    先落 `prepared` 意图再联系 HA；已有结果同键重放不再发第二次调用；`unknown` 保留且不自动
    重发；`prepared` 重试先按观测对账（已到目标记为 `observed/recovered_at_target`），否则才
    发出一次目标状态动作；回执写失败返回 `durable: false` 而不报假失败。受理（回执）与观测
    （受理之后的 `GET /api/states`）分别表达为 `acceptance` 与 `observation`。
  - 边界：只支持 `light`/`switch` 的 `turn_on`/`turn_off` 与只读 `sensor`；拒绝重定向
    （`allow_redirects=False`）、请求总时限（1–15 秒）、响应上限 1 MiB、目标只可能是已登记实体；
    令牌只从环境变量读取，响应与日志不含地址、令牌或 `Authorization`。
- `services/platform/web_console.py`：构造 `Home`，把 `/api/web/home/` 前缀交给它，并在操作后
  重新核验会话与策略指纹。设备控制使用独立解锁 `session["devices"]`，与 `models/unlock` 互不授予。
- `services/platform/service.py`：允许新的顶层设置键 `home`。
- `services/platform/auth.py`：动作词表新增 `device.control`（不使用 `config.*` 冒充设备权限）。
- 运行产物 `<db>.home-controls.sqlite`：`readings`（读数、采样时间、修订号、尝试结果）与
  `control_intents`（意图、语义摘要、结果码、目标状态是否出现在回执中）。不含端点与凭据。

### 网页（apps/web）

- 新增 `apps/web/src/features/home/{HomePage.tsx,api.ts,home.css}`：`/#/home` 的家庭设备段。
  登录复用同源 Cookie/CSRF；控制需再次验证管理员密码解锁；只读传感器不显示动作并明确说明；
  读数按可用性显示“当前/读数已过期/无法读取/设备不可用/状态未知/尚未读取”，离线时保留值但
  标为“上次读数：…”。受理、回执与后续观测分开显示；未知结果提示“不会自动重发”；等待期间提供
  “取消等待”，取消只停止本页等待并提示重新读取，不声称未发出或已回滚。冲突后自动重读并保留
  冲突原因。只用既有 `.panel`/`.button`/`StatusRail`/`StatePanel` 与设计 token。
- `apps/web/src/app/modules.ts`：新增 `home` 的 lazy 注册（协调授权）。
- `apps/web/src/app/App.tsx`：新增一行页面挂载 `#/home` 段 0（协调授权；其余壳未改）。

## 风险与限制

- 没有真实 HA 实例、真实设备、局域网地址或生产部署；证据全部是本机 loopback 合成 HA 与隔离
  合成控制台。根 `runtime_routes_enabled=false` 与 `runtime_disabled_until_joint_acceptance` 仍有效。
- 只实现了开关类目标状态动作：亮度/色温/窗帘位置等参数动作、场景调用与 WebSocket 状态订阅都不在
  本轮范围；HA 侧自动化与乐观状态竞争只按观测如实显示。
- Windows 上连接无人监听的 loopback 端口表现为超时而不是拒绝，因此离线用例接受
  `device_timeout`/`device_unavailable` 两者，不把它当作已确认的“未送达”。
- 控制权限是单机单管理员模型：无逐设备审批、无操作审计查看页、无并发压测。
- `<db>.home-controls.sqlite` 与权威库必须一起备份；单独恢复权威库会丢失幂等与恢复能力。
- `npm run format:check` 在仓库范围内仍有**先前就存在**的失败文件（未被本任务修改的旧交接与
  平台文档）；本次只格式化了自己新增/修改的文件，未顺手改动无关文件。
- 浏览器套件依赖 `TS012_CONTRACT_DIR` 指向已发布 `text-dialogue/v1`，并依赖本机
  `%LOCALAPPDATA%\ms-playwright` 已装的 chromium（TS-016 记录的离线安装方式），未改动任何
  Playwright 配置文件与依赖锁。
