## 3. 关键实现决定（供审查）

1. **先 fsync 再确认**：`emit_durable` 只在 fsync 返回后推进 `_synced`；「已确认」不等于「可能在
   内存里」。
2. **容量耗尽拒绝新业务**：目录到上限时 `ready=false` 且新业务 503，不静默丢记录、不假装健康。
3. **日志失败不重发副作用**：出站调用失败或取消只记录，不因日志问题重试已发出的动作。
4. **未知不等于健康**：`not_verified` 与 `non_durable` 都阻塞就绪；探针拿不到锁或超预算时全部报
   `not_verified`。
5. **`not_configured` 是部署选择，不是故障**：只核对本部署**实际拥有**的 sidecar 台账。实现初期
   曾对四个台账一律索要，导致未登记家庭设备的部署永远无法就绪；已按能力启停修正，并有专项用例。
6. **探针不写日志**：探针请求（含未通过认证的）不产生任何记录；业务请求全量登记、不采样。
7. **就绪凭据独立**：`ready_token_env` 复用任何已登记业务凭据会被启动时以 `invalid_input` 拒绝。
8. **合同按原始字节固定**：manifest 覆盖 CRLF 文件，任何行尾规范化都会失败；`Contracts` 自身的
   LF 规范化不适用于诊断包。
9. **只读就是只读**：数据库只用 `mode=ro`（从不用 `immutable`），`PRAGMA query_only=ON`，探针
   不建库、不迁移、不写文件（有源码级与行为级两类用例）。
10. **取消与失败分开**：`asyncio.CancelledError` 记录 `cancelled` 后原样重抛，不折叠成 `failed`。

## 4. 风险

| 风险                                                          | 影响与缓解                                                                                      |
| ------------------------------------------------------------- | ----------------------------------------------------------------------------------------------- |
| **容器镜像从未构建、从未运行**                                | 最高风险项。`Dockerfile` 只经过静态核对；层缓存、非 root 写权限、`HEALTHCHECK` 实际行为均未验证 |
| Windows 上 `loop.add_signal_handler` 抛 `NotImplementedError` | 已回退到 `signal.signal`；POSIX `SIGTERM` 路径**未在 Linux 上验证**                             |
| 诊断合同状态为 `development_frozen_pending_joint_acceptance`  | 联合验收前合同仍可能变更；manifest 哈希已按协调方更正固定，若合同再变必须重新核对               |
| 日志目录无保留期/轮转删除                                     | 到上限即拒绝新业务（刻意的），运维侧需要自行归档或扩容，否则长时间运行会触发 503                |
| `preflight` 在首次启动前报 `requires_initialization`          | 这是正确语义而非故障；编排脚本必须区分「未初始化」与「坏了」，否则会把首启判为失败              |
| sidecar 台账纳入就绪检查                                      | 台账与权威库必须一起备份；删掉台账会让 `sidecars` 转红                                          |
| 真实对端（核心网页、人格、HA、静态上游）可用性                | 不在本卡范围；`credentials: ok` 只表示变量在环境里，不表示对端可达                              |
