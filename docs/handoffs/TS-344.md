# TS-344：内置 SDK 身份接线与最终本地写入排空

基线 `b9430e3849d3cca8d5e8329bf70dad9aa4e76e8d`，隔离分支 `codex/unified-onebot-platform-20261027`。仅本地候选，无产品 main 合入、推送、部署、真实 SDK/QQ/模型或生产数据。

`Platform(..., adapter_clients=None)` 透传明确的 connection_id→session 工厂到原 BotAdapters。另提供 `platform.bot_adapters.bind_owned_adapter(instance_id, session_factory)`，由宿主在两个 owner loop 内完成绑定：OneBot 只返回其原持久 SDK instance_id 字符串，Platform 绑定相应内部工厂。该身份后续新增的群/私连接直接复用，不需要为每个新会话维护路由配置。

只有明确连接或 SDK 身份命中才走内部会话，exchange 仍检查唯一目标与固定 origin。所有未绑定连接继续原 reviewed_pins/DNS/TLS 路径；同 URL 或同 adapter kind 不代表内部身份。初次网页 probe 尚无 SDK 身份，保留原网络行为；不改连接数据、密钥、权限、发送资格或回执。默认不注入时构造及调用保持原路径，不给旧调用方无故增加 None keyword。

独立联合发现 final cleanup 的实际缺口：后台/HTTP 等待者取消后，已受理 LocalWork 数据库线程仍可能运行；原 Platform.close 立即关闭线程池及存储。现在原 AppRunner cleanup contexts 停泵之后，最终 close_local_work 先 await 原 LocalWork.drain，再关闭存储。新增回归持有真实 SQLite 写事务、取消等待者并验证 cleanup 仍等待，释放后写入成功且运行态才变 closed。没有改变 SQLite 线程属性或锁规则。

验证使用已有 q21 Python、固定 text-dialogue 原字节合同及协调根 `210c342` 的真实 LocalExchange；仅 loopback/隔离 SQLite 和合成 SDK 应答。
