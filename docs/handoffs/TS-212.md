## 修复与复用

根因位于既有 `Tasks._task` 的公共详情组装：基础设施和媒体分支提供 request/evidence，但没有 TaskDetail 必需的 timeline。现在使用责任模块现有记录的真实 `created_at` / `updated_at` 补上记录时间和更新时间，保留原始精度。家庭与模型自身更丰富的时间线完全保留；基础设施结案时间直接取持久 operation 的 `finished_at`，没有时仍为 null。媒体没有可靠的结束/观测时间，因此不把更新时间冒充这些事实。列表投影不增加详情字段，不新增台账或执行路径。

首个 timeline 异常还遮住了同链路的第二处违约：真实 infrastructure evidence.result 为对象，containers 与 media_servers 为数组，旧 TaskEvidence 类型和 show() 只支持标量。现在类型准确表达 JSON 递归值，复用原 show() 递归展示结构化依据；null 仍显示“—”，unknown 仍为“未知”。补本次实际字段的中文标签，新增通用值采用“未配置”“部分结果”等对各来源均准确的词，未将媒体状态套成健康检查。没有使用前端空对象兜底隐藏生产者缺字段，也没有暴露原始 payload/配置/秘密。
