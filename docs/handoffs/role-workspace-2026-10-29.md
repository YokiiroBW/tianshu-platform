# 角色工作区、Web 聊天与书架

本地候选，基线为 Platform `31f7bcc41e1a6097b566d0da2ae27aef34a1b06f`，分支 `codex/role-workspace-20261029`。本批未合入协调检出、未推送或部署 NAS；根工作区原有改动保留。

## 交付

- 共享 `RoleWorkspace` 贯穿角色子导航、聊天、生活、日记、创作、人格、角色模型和小屋。原小屋书签跳转到角色子页；管理目录不可读时，保留当前会话原有授权聊天角色的选择能力。
- Web 聊天复用真实 `DialoguePanel` 的授权会话、历史分页、发送、取消和状态读取，增加角色名称、Enter 发送、Shift+Enter 换行与跟随最新消息；运行诊断放入展开项。
- 日记、作品、研究资料、资产条目复用 `BookShelf`，正文和编辑复用 `Drawer` 及既有读取/编辑接口。生活分为总览、活动与关注、经历与记忆、衣柜、阅读与学习、生图与相册；没有新增第二套生活或资料服务。
- 机器人账号采用连接卡片；创建后立即回到列表，展示等待握手的服务；地址和 Token 放在连接详情，短 Token 给出格式说明。管理解锁和原回复策略保持。
- `POST /api/web/roles/delete` 复用原停用协调，完成 Core、Memory 等既有撤销后才标记删除；失败可重试，保留历史数据，重启不重新启用。
- `POST /api/web/roles/models/view`、`.../apply` 在原角色记录内保存功能模型。主对话复用原角色主模型；其他功能按角色指定、全局功能默认、角色主模型、系统默认回退。编辑器和运行选择共用 `effective_binding`。两个编辑入口的主模型修改互相失效陈旧表单；没有增加模型凭据副本或数据库迁移。

## 实际验证

TypeScript 检查和生产前端构建通过；构建保留既有 Three 渲染分块超过 500 kB 的提示。改动 Python 文件的 Ruff 检查通过。

`test_role_workspace` 5 项及原 `test_model_functions` 12 项通过；另直接复用原 `test_role_runtime` 的双角色重启/停用、取消中断恢复、双 owner 撤销 3 项，合计 20 个定向用例。均使用临时 SQLite 和合成上游，没有执行 PG 矩阵、真实 QQ 或付费模型调用。

测试最初遇到 Python 二进制依赖版本差异和本地契约副本不一致；已将项目声明的必要测试依赖装入忽略目录，并从已有本地发布副本收集与当前代码固定哈希匹配的测试契约。未修改产品的哈希校验、根合同或生产配置。此定向验证未加载 `memory-context/v2`，不据此声称其另有不匹配的本地副本已修复。

浏览器使用真实页面组件和完全拦截同源 API 的合成预览，检查角色切换、日记阅读、生活刷新、模型独立选择、聊天发送、机器人创建及卡片展示、角色新增和删除。此结果验证交互，不是线上业务验收；移动端和真实资产服务未做实机验收。
