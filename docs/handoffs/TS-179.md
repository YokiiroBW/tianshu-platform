# TS-179 音乐歌词自动补齐

基线 `ec5671a`，独立分支 `codex/ts-179-music-lyrics`。用户授权覆盖新下载及已有曲库、跨渠道补词、失败低频重试、音频去重、Navidrome 滚动歌词和翻译验收，完成后提交推送部署。本提交为候选，部署与实机结果待补充。

## 实现

- 复用统一录音索引、媒体文档和扫描租约，独立后台维护歌词；新归档自动登记，启动后补登记已有歌曲。不同歌单引用同一录音只维护一份。
- 复用 `Resolver.matching_tracks` 的严格版本/歌手/时长/专辑/ISRC匹配与已绑定渠道，不调用音频取源或下载接口。共享既有账号请求预算、间隔和冷却；失败渠道不会阻止其他渠道补词。
- 有时间轴及同步翻译的本地歌词直接复用。其余尝试已连接渠道，保留更完整的同版本歌词；失败从6小时指数退避至7天，缺词每7天补查，并错峰。每分钟处理一首，避免首次回填突发请求。
- 原文、翻译和罗马音分别保留；对齐时间轴的原文/翻译组合为标准同名 `.lrc`，原文另存 `.original.lrc`。新下载把双语文本写入标签；已有音频字节保持不变，Navidrome 使用优先于内嵌标签的本地 LRC。
- 小型歌词文件写入有持久意图、原子替换和中断恢复，更新曲库、历史回执及发布清单；不创建音频任务、不退役现有音频。歌词缺失/变化不再使可复用的音频失效。
- 音乐详情页展示补齐进度、滚动歌词、同步翻译、来源及等待重试状态，不加入概览。

## 验证与边界

Windows 初轮完整音乐回归161项无失败、5项环境跳过；其中一个复述既有行为的测试随后移除。新增针对性测试覆盖跨源匹配、错版/歧义拒绝、时轴对齐、纯文本升级、重复执行、并发租约、退避、旧库回填、音频升级和中断恢复。网页桌面/手机26项通过，类型检查与构建通过。最终固定提交的Linux镜像验证、生产发布和Navidrome实机核验将在交付时补录。

初轮导入路径错误及Windows分隔符错误已修复；测试错误与中断记录留在忽略的 `.runtime` 目录。没有修改依赖、全局设置或其他产品。上游没有歌词/翻译、匹配不唯一或歌词时轴不相符时会保留已有内容并低频补查，不生成或猜测翻译，不声称所有歌曲都有完整歌词。

Navidrome 0.64.2 官方 `core/lyrics` 与 `model/lyrics_lrc.go` 源码用于核对外置LRC优先级及时间轴解析；实际播放显示仍以部署验收为准。
