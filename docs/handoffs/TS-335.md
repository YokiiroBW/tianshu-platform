## 最小装配合同

```python
platform = Platform(settings, internal_clients=exchange)
console = WebConsole(platform)  # 或显式 internal_clients=exchange
private_app = create_app(platform, console=console, trusted_local=exchange.owns)
public_app = create_app(platform, console=console, public=True)
```

`internal_clients` 是宿主提供的 exchange；`session_factory(name)` 可在模块注册前绑定，实际请求时核对明确目标与注册 origin。Platform 在构造时绑定 `companion/memory/knowledge/gateway` 四个工厂；WebConsole 默认继承同一组。低层客户端只接可选 `session_factory`，不依赖宿主源码或根检出路径。未注入时仍在各原模块通过 `aiohttp.ClientSession` 访问真实网络，保留 TLS、CA、pin、凭据、请求/响应预算与错误语义。

明确内部注入时省去 TLSContext、TCPConnector 和 cookie jar；Gateway 保留 `auto_decompress=False`，对应 TS-334 的应用原始字节语义。内部 URL 是原已验证配置中的逻辑合同标识，没有监听、DNS 或 TLS；收到的请求实际 `secure=False`。`trusted_local` 只在 private boundary 生效，须由宿主以 `exchange.owns` 提供，header/URL 不能替代它。原 token 鉴权、来源证明、schema、权限和回执仍照常执行。公开 UI 不接受此替代。

| 明确目标 | 接入的原客户端归属 |
| --- | --- |
| Companion | Sources 的 core_post；WebDialogue snapshot/cancel；RoleRuntime core；PersonaClient 与共享该 reader 的 WebPersonaAuthor；WebReader life；WebLifeManagement life/images/skills/retry；BotAdapters 的 core 分支及经它调用的 BotObservation |
| Memory | RoleRuntime memory；WebMemory；GroupMemory topics/archive-check；WebMemoryLinks；relationships.Client；QQ 别名观察与 profiles |
| Knowledge | RoleRuntime knowledge；WebReader knowledge；WebContent 的 JSON、原件读取与原始上传 |
| Gateway | ProviderManagement.gateway_request；实际外部 provider 仍由原 Gateway 拥有 |

RoleRuntime 按 core/memory/knowledge 登记配置对象的明确归属选择工厂，不比较 URL 来猜目标。GroupMemory 的 Chat evidence 保持原网络路径；AssetLibrary、HA、weather、设备、媒体服务/CDN/provider、外部插件 RPC 和漫画 Unix socket 均不注入。没有全局 patch ClientSession，也没有新凭据库或逐模块切换环境变量。

## 生命周期

新增 `await services.platform.server.quiesce(private_app)`，仅宿主显式调用才改变原运行流程。正常启动、cleanup_ctx 顺序和最终 Platform.close 保持；无监听的 `AppRunner.setup` 可以运行原生命周期。

宿主须先停止新的 root 入口，再调用 quiesce，等待在途调用及必要回调排空，最后调用 exchange.close / AppRunner.cleanup。callback 路由、token/授权、账本和连接池在排空期间保持开放。总时限由宿主持有；超时或强制退出不能宣称已 drained。

- 插件：单独停止 scheduler，等待已接受 invocation、其合法 child callback/action 和安装任务，不关闭 worker、漫画辅助角色、vault 或 repository。comic 进程监视任务留到最终 close。root 准入由宿主停止，不能以 closing 状态阻断现有 callback。
- Media：只停止原 Background loops，沿原取消/lease/回执语义收尾；不关闭来源/发布 client、books/comics 或 ledger。最终 cleanup 才关闭资源。
- Infrastructure：停止 poll/claim pump，等待已接管的观测、日志和 control RPC，保持 Executor/repo；第二个尚未领取的 intent 留 queued。外部操作仍可能运行，sent 位和未知回执保持，重启沿原 operation.get 对账，不重发。
- BOT/alias/role：停止原 server pump 并等待其取消结算；BotObservation 的 batch/pending_local 收尾拆出 quiesce，原 close 委托同一实现。最后 `LocalWork.drain` 等待真正仍在运行的本地操作，不关闭 callback 准入和 Store；普通 run 与 TS-338 的 run_settled 语义不变。

quiesce 不是“整个 Python 默认 executor 已空”的断言。Media 既有 source HTTP fetch、engine 文件 hash 读取和可选 shared metadata cache 的 `asyncio.to_thread` 不在 LocalWork 计数；它们取消后可能短时继续，未在本卡全媒体扫改或关闭全局默认 executor。权威账本/主要文件写走原 LocalWork/settled 或原 owner 跟踪。统一宿主最终默认线程池与总退出期限仍由协调装配处理。
