# TS-414 Provider 测试时间 PostgreSQL 类型修复

基线 `47b503e1ed8616365fd421fb3abbcc4397aa4b14`；隔离分支 `codex/ts414-provider-test-pg-20261029`。

## 问题与根因

R22 实机自主目标在 preparation/query 返回 403；Platform 角色虽具 memory.read/write，却为 pending/verify，error_code=provider_store_unavailable。角色重启复核首先执行 RoleRuntime._provider → ProviderCatalog.view。

view 遍历全部 provider，对失败或 unknown 的测试读取 test_attempts，比较 json_extract(result,'$.tested_at') 与 float tested_at。Platform PostgreSQL numeric vocab 漏掉 tested_at，转换表达式返回 TEXT，PG 报 42883（text 与 double precision 无可用相等操作符）。因此新增非成功模型测试可使整 catalog view 失败，连带阻断跟随默认模型的角色重启复核和后续 actor memory 授权；与 Gateway 容量、角色缺少读权限不是同一问题。

## 修改

只在 services/platform/postgres.py 的 NUMERIC_PATHS 加入 tested_at，让既有转换器将该 JSON 数值转为 double precision。沿用现有 JSON/NULL 和参数绑定语义，不迁移数据库，不删除/改写失败测试记录，不放宽角色权限或直接改 pending 状态。未修改 Memory/Companion、共享 storage、前端、依赖或锁。
