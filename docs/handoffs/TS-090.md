## 4. needs_validation：ruff 0.15.7 不可得

卡要求在本任务可用环境运行 ruff。本任务 worktree 内实测：

1. `python -m ruff --version` → `No module named ruff`。
2. `python -m venv .runtime/venv` 后安装 → `ensurepip` 非零退出（沙箱拒绝其临时目录写入/执行），venv 无 pip。
3. `python -m pip download ruff==0.15.7 --no-deps` → 120 秒超时，无网络出口。
4. 对着 bundled `site-packages` 做离线 `--find-links` → `No matching distribution found for ruff==0.15.7`。

未采取的绕过（按边界要求）：未改系统权限、未改 `sitecustomize`/`tempfile`/ACL、未使用其他任务 worktree 的 venv、未在他人环境写缓存、未新增依赖或锁变更。替代证据见 §3 的替身静态检查；真实 `ruff format --check` / `ruff check` 结论需在有 ruff 0.15.7 的环境补跑。日志：`logs/ruff-unavailable.log`。

## 5. 测试发现兼容性（已实测，未改旧入口）

`tests/backend/media/` 为**命名空间目录**（无 `__init__.py`）：

- 卡中命令 `discover -s tests/backend/media` 把该目录作为顶层目录，5 个模块全部被发现并 122 项通过。
- 宿主约定 `discover -s tests/backend` 只递归含 `__init__.py` 的包，因此不会进入 `tests/backend/media`（实测该命令下 media 模块不出现，不报 media 相关错误）。
- 未添加 `__init__.py`：加上后整仓发现会把测试包注册为顶层名 `media`，与生产包 `services.platform.media` 同名冲突，反而使两套发现都不能稳定运行。
- 整仓回归需显式加最窄套件：`discover -s tests/backend/media`（或对每个测试文件单独指定）。本卡未改任何旧测试入口或断言。

同一环境运行整仓 `discover -s tests/backend` 时，13 个既有模块因 bundled 解释器缺 `aiohttp`/`jsonschema` 而导入失败——与本改动无关（未引入依赖，也未触碰这些模块）。
