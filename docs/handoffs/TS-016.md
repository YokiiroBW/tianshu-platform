- `services/platform/service.py`：允许新的 `web_models` 设置键。

### 修复的真实缺陷

网页发布文档的有效期窗口原先直接取 `time.time()` 原始读数：合同的时间戳编码会把微秒四舍五入，
而写事务随后用同一时钟再做一次 `published_at <= now` 检查；Windows 时钟粒度较粗时两次读数可能
落在同一个 tick 上，向上取整的时间戳就会比检查点晚约 0.5 微秒，发布被误判为 `invalid_input`。
表现为约一半概率的间歇失败（连续运行 20 次可复现）。修复方式是把窗口锚定到请求所在的整秒，
使时间戳在合同编码中精确往返、窗口长度恒等于 `lifetime_seconds`。修复后同一场景连续 20 次通过。

## 风险与限制

- 没有真实模型账号、供应商调用、付费模型、真实设备或生产部署；全部证据是合成 fixture 与本机
  loopback HTTP。根 `runtime_routes_enabled=false` 与 `runtime_disabled_until_joint_acceptance` 仍有效。
- 重放账 `<db>.web-models.sqlite` 只存 client_id/semantic/target/version，不存配置内容；删除它只
  会让重放不再被识别，不影响配置权威。它不随权威库自动清理，长期增长需要后续维护。
- 网页管理是单机单管理员模型：没有双人复核、没有按版本的分页（最多列最近 20 版）、没有并发压测。
- `npm run format:check` 在仓库范围内仍有**先前就存在**的失败文件（`docs/handoffs/TS-013/015/064.md`
  与 `docs/platform/{assetlink,native-model-config,source-sync*}.md` 等未被本任务修改的文件）。
  本次只格式化了自己新增/修改的文件，未顺手改动无关文件。
- Playwright 官方 CDN 在本机不可达（`cdn.playwright.dev` ECONNRESET）；浏览器二进制改用
  Chrome for Testing 官方存储/镜像的同一版本（153.0.8010.12 = playwright chromium v1243）安装，
  见 `.runtime/dsh-delivery/delivery.md` 的环境说明。
