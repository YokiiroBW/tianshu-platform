## 实现与复用

控制领域位于 `services/platform/infrastructure/`：Control 后台调度、ControlRepository 原子领取与台账、ControlClient 固定协议、control_projection 用户投影、control_web 请求/缓存读取分别负责。复用原 Executor 的唯一受限交换、进程树、环境白名单与输出上限，复用 LocalWork，不另起 SSH/子进程体系或凭据系统。

同源 `POST /api/web/infrastructure/control/{view,detail,plan,execute,action,operation,operations}` 沿用管理员 Cookie/CSRF/Origin/external.manage，无密码解锁或多确认。普通容器/栈启停重启一次受理；创建、配置变更、镜像更新、版本恢复先具体预览，再执行 plan_id。节点/栈/full64 容器身份与连接修订分开校验。详情支持准确容器 inspect，受保护对象显示维护归属，不冒充普通控制成功。

控制表放在原 `.infrastructure.sqlite`，按 node_id + plan_id 限定计划作用域。发送前持久化 sent 位，多个平台实例通过事务/owner/lease 领取；同栈串行，未知且 worker 活跃或未确认时保留占位。发送后断线、取消和重启只查询原操作，收到可校验的明确未受理拒绝才终态失败。陈旧连接修订不投递到新配置。HTTP 不等 SSH，离开页面仍继续，执行终态自动排控制详情与原只读状态刷新。

运行、健康、命令和 execution_active 分别投影；none 表示未配置健康检查，absent/mixed 保留实际来源含义。未知命令不因运行观测达成而成为成功。任务中心从同一台账读取 `platform.infrastructure`，中文标题和已核对目标名、完整 ID 详情，链接为既有 `#/home/1`；pending 按 settled，不因命令已观测而掩盖仍活跃的 worker。

公开回执/任务中心只有脱敏结果，不含内部待执行 compose payload、凭据或原始命令输出。配置编辑保留 opaque 秘密标记；新配置输入的秘密也由节点在预览前掩码。恢复按节点计划处理受管配置版本，不能承诺 `.env` 始终维持当前值，亦不能声称回滚已经写入的数据。卷和 bind 数据不通过此控制删除。

职责外必要薄接线已获协调者精确授权：`web_console.py` 只为 control/plan 放开 1 MiB JSON；`test_tasks.py` 只为真实新增源补一行空流夹具。未改 frontend、media、依赖锁、公共 service/server、根合同或根任务板。runtime 跟踪并排空自己提交的 LocalWork，解决取消后 SQLite 尚在完成时 Windows 清理占用的问题。
