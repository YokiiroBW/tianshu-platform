# TS-304 BotDelivery 执行后错误归属

基线 `c1d339e3a82553b7f6586a15e3ef421f76dfcda0`，分支 `codex/ts-304-memory-q20`。本号只修改 `server.py` 和既有 C4 HTTP 测试；未改 Delivery 账本、LocalWork、SDK、协议、媒体或并发配置。

`send/finalize/cancel` 在现有 LocalWork 完整 operation 真正进入时设置请求独占的 `threading.Event`；worker 不访问 aiohttp request。此后通用异常、typed 5xx Fault 以及无法归为明确业务校验的编码异常保守返回 `unknown/retryable=false`。明确 schema/auth/权限/业务 4xx 拒绝、日志准入和 executor 尚未启动的拒绝保留 `not_started`；`query/context` 沿用原语义。没有新增重发或发送带释放路径。

这是可触发合同错误修复，不是对恢复134中 q1 的原现场阶段认定。Platform append 只持久化队列，SDK 发送仍由原 claim/send/ack owner 执行；查询 `receipt=null` 只表示该次查询未找到 expression，不能代替未执行证明。

稳定 runtime patch：`.runtime/ts304-validation/runtime.patch`，SHA256 `dfb4d646830dfd054b9274f26a726546ff2d60ade6247f7f9ad0318f819195c3`，根已独立逐行审查。相关完整 diff 和格式/ruff/diff-check 已核。
