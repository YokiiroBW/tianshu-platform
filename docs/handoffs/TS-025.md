### 真实链路与替身边界

真实联合验收用 Core 自己的固定提交 `0a775631366f1b7c4bab94ac5b16e67aa15ee1ab`（`git merge-base
--is-ancestor` 证其在 `main` 上）导出到本 worktree 忽略的 `.runtime/companion-joint`，经 uvicorn 在真实
loopback TLS 上服务（证书一次性生成，不装系统信任），用真实 `persona_admin` Bearer 写入合成修订/批准/
发布/回退后读取四类历史、单版本、两版比较，并验证生产者的分页游标、`version_conflict`、越权角色 403
与**回答里不出现凭据或地址**。`TS013_TLS_PYTHON` 只用于生成临时证书，Core 进程与页面仍用本任务虚拟环境。

浏览器套件的角色服务是**同进程合成装置**（真实 TLS、真实 aiohttp，但数据是合成的 `Synthetic` 类），
三个控制台是真实部署差异而不是状态替身；它与上面的真实联合验收分别记录，合成装置不替代真实联合结论。

### 已记录的真实差异（needs_coordinator）

部署登记的角色若**没有声明版本**，真实 Core 存 `imported: null`，而候选 schema 的 `revision` 要求
整数：该角色在目录里因此显示为 `error: invalid_upstream`，页面如实说「回答无法使用」，不隐藏也不放宽
校验。此差异在 `test_personas_joint.py` 中以真实 Core 复现并断言，属候选包与生产者实现之间的**待协调
事项**；本地未改 schema、未改 Core、未加兼容分支。
