# TS-246：本地执行队列满载时异步背压

## 范围与基线

- 分支：`codex/ts-246-pg-backpressure`。
- 精确基线：`14c2d1a33579f0c8e7b41da6422b1b6115b2419e`，不含协调检出的未发布插件。
- 协调者实机捕获 `book_audio → BookAudio.loop → reconcile → LocalWork.run` 在容量16满时抛出 `Fault`，SQLSTATE为空，导致媒体 Background 进入 recovering，并使 readiness 的 runtime 检查失败。
- 本卡唯一运行源码改动为 `services/platform/local_work.py`；其他改动为并发测试、原测试预期更新及本交接。默认4线程、16个已提交在途操作保持。

## 实现与行为

复用 LocalWork、线程锁和真实 executor Future 的完成回调。满容量调用进入 FIFO 异步等待队列，事件循环继续工作；队首直到实际取得容量才出队，新调用不能插队。取得容量后只提交一次完整操作，事务不会拆开或重放，调用方的 ContextVars 继续传入执行线程。

- 等待容量时取消：移除等待者，不提交操作，并通知下一位等待者。
- 已提交后取消：保留原来的 `future.cancel()` 语义。尚未开始的任务可以取消；正在执行的任务直到真实 Future 结束才释放容量。
- 操作异常或提交失败：传播原异常并释放相应容量，不重试业务。
- `close()`：先标记 closed、唤醒所有容量等待者并拒绝它们，再取消 executor 中尚未开始的任务。正在运行的线程继续拥有容量直至完成；重复 close 可用。
- 通知通过等待者所属事件循环的 `call_soon_threadsafe` 投递，支持工作线程完成和异线程 close。等待者取消、已唤醒尚未恢复时取消、已唤醒尚未恢复时 close 都有明确测试。

没有调整 readiness 判定、探针预算、PG/Redis配置、存储共享包、后台任务状态或业务授权判断。
