## 改动与归属

容器清单此前没有高度约束，100 行撑长整个页面；左栏使用自动最小尺寸的 grid，按钮的内容最小宽度会越过卡片。修复全部位于基础设施模块，未改公共壳、令牌、路由、后端、合同、采集器、媒体、登录或依赖。

- `ContainerPage.tsx`：左栏节点/Compose 分别设滚动选择区；清单的标题、筛选、分页保留在卡片内，观测摘要及条目在正文中滚动；详情标题和状态固定，其他详情在正文中滚动。切换节点/筛选/页码时清单回到顶部。行内名称与镜像省略并保留 title，详情另列完整名称及原有完整镜像。继续复用 `StatusRail`、`NodeRail`、`Freshness` 和既有查询/动作端口。
- `infrastructure.css`：三卡桌面同高，左栏改为纵向 flex 并显式消除内部及按钮的自动最小宽度；清单/详情的 flex 正文允许收缩并独立滚动。通过基础设施工作区的实际宽度重排两列/一列，手机各卡仍有界。桌面筛选标签与控件同行节省空白，手机保留上下排列。资源区以 `clamp(10rem, 28%, 26rem)` 在普通桌面紧凑显示、超宽屏适量展开。
- `ContainerResourceMeter.tsx` 与 `container-resource-meter.css`：行和详情共用 CPU/内存读数、资源条与说明，复用既有字节和百分比格式及设计令牌。

CPU 沿既有单核 100% 口径，显示真实百分比；超过 100% 时仅视觉填充封顶。内存优先有效的 `cache_adjusted_usage_bytes`（含真实 0），否则读取 `raw_usage_bytes`，仅在有效 `limit_bytes > 0` 时计算百分比；保留字节、限额、缓存口径和来源。无读数或无有效分母显示 `—`，不制造 0% 或 100%。已知值使用 `role=meter` 及真实百分比 aria 值，超 100% 时 aria 最大值同步容纳实际值；未知值不生成虚假的 meter 值。
