## 交付内容

`services/platform/backends.py` 装配共享连接、绑定、只读检查和关闭；`services/platform/postgres.py` 由产品维护真实表、类型、JSONB 运算、权威触发器、索引、事务与 SQLite 导入。共享包不包含业务 schema，也不把 SQLite 文件或业务大正文当成 PG BLOB。

默认 SQLite，另支持 `storage_backends` JSON 设置和 `TIANSHU_POSTGRES_URL`、`TIANSHU_REDIS_URL`、`TIANSHU_STORAGE_NAMESPACE`。原有 `storage=sqlite_local`、`database_path`、目录中的 `sqlite_path` 继续作为本地文件锚点。首次未绑定且 PG 不可用可以继续 SQLite；一旦 pending/active，失联、配置删除或目标变更均不能回读旧 SQLite。

已接入的 SQL 所有者：

| 所有者 | 当前后端内容 |
| --- | --- |
| `Store` | 来源、映射、权限、人物、模型配置/版本/撤销、审计与权威序列 |
| providers / external / bot adapters | 既有加密目录、修订、连接和来源证明；密钥保持原私有文件 |
| web inputs / replies / models | 输入去重、持久发送、模型发布意图/回执 |
| HA | 当前控制及全部历史 `home-controls.external.<revision>.sqlite` 对应账本 |
| bots / observation / roles / QQ admin | 发送与未知结果、观察、角色执行、QQ 管理全部持久账本 |
| web account | 管理员账号表；原 `.sealed` 封印仍为文件且参与损坏/回退检测 |
| infrastructure | 已登记配置、观察、容器/项目操作与恢复账本 |
| media | 订阅、扫描、下载、音乐/书籍/听书/漫画任务、进度和文件索引 |

SQLite 导入保留源文件，逐表核对类型化内容与数量，保留版本、索引、序列和业务状态。业务认领使用 PG 事务、唯一约束和数据库/schema 级事务锁；可预期插入冲突使用原生冲突语义，已有需局部捕获的意图插入使用共享 savepoint。未用 Redis 代替任务账本或权限判断。

## 本轮最终修正

- pending 绑定也使用只读 PG 路径；`preflight` 明确失败并给出 `requires_initialization`，没有读旧 SQLite 的成功结果。仅正常启动可以恢复迁移。
- 每个 PG schema 的 `_ts_schema_metadata.table_names` 记录历史业务表。ready 目标先校验完整表集，再执行任何产品 DDL；已丢表拒绝启动和就绪，不能 `CREATE IF NOT EXISTS` 出空账本。新表及清单在同一事务发布，prepare 不提交共享层持有的迁移事务。
- `providers-init` 实际读取绑定，pending/active PG 时在创建目录、SQLite 或新密钥前拒绝。首次未绑定仍先执行原有私有目录/密钥引导，再由完整服务启动导入。
- 管理员读取、配置移除检查和只读探针读取当前 PG，仍核对原文件封印，不能退回部署旧密码。
- 观察发现表的 UPSERT 明确限定计数列；可空分页参数显式转换为 TEXT，修复真实 PG 的歧义/未知参数类型。
- 三个 HA 测试的合成服务挂起窗口由 2 秒设为 10 秒，覆盖 PG 启动和登录开销，产品超时与恢复策略没有改动。

## 文件化及备份新增目录

`services/platform/payload_files.py` 复用共享 FileStore。先原子写入不可变内容并校验，再允许 SQL 提交引用；读取校验哈希和长度，按原 API 恢复内容。

| 原 SQL 内容 | 引用及文件根 |
| --- | --- |
| `book_chapter.content` | `content_ref`，`Path(media_db).with_suffix('.book-content') / 'chapters'` |
| `book_audio_job.text` | `text_ref`，同一章节内容根 |
| `music_lyrics.pending.writes[].content` | `content_ref`，`Path(media_db).with_suffix('.lyric-content')` |
| bots `replies.request.media[].data` | 二进制 `payload_ref`，`str(bots_db) + '.payloads'` |

例如主锚点 `platform.sqlite` 的新增根为 `platform.sqlite.media.book-content/chapters`、`platform.sqlite.media.lyric-content`、`platform.sqlite.bots.sqlite.payloads`。迁移现有 SQLite 时也外置上述旧内联内容，不改变修订、语义摘要、认领租约、发送状态或未知结果对账规则。base64 极少数合法但非规范填充位的原始拼写另存 `encoded_ref` 文件，保证原请求摘要完全一致。

现有成品、暂存、分片、封面、漫画扩展包、硬链接和用户书库根保持原职责。SQL 事务失败可以留下尚未引用的不可变文件，本批不自动清理，也不对可靠恢复材料设 TTL。

部署/备份必须把以上三类目录、既有媒体/暂存目录、私有目录加密密钥、管理员封印和 `.tianshu-storage-platform.json` 后端绑定文件，与 PG 一致快照配套。单独 PG 备份不够；迁移后的旧 SQLite 也不包含之后新增业务。恢复须还原同一时间集合与文件锚点，不能删 PG URL 当作回退。后续根部署包应纳入这些目录；本卡没有执行生产备份恢复。

## Redis 范围

- 音乐元数据：现有操作 TTL（通常 3600 秒，较稳定详情 86400 秒），键含供应商、账号修订/凭据摘要和参数；刷新回源，命中不续期。
- 天气：成功 300 秒，错误/旧结果重试 60 秒；配置修订、服务、地点、语言与单位隔离；每次仍做现有角色授权和读后修订检查。
- 媒体容量分类：300 秒，节点/文件锚点/挂载目标/卷范围隔离；强制刷新删除当前键，实时剩余容量仍现场读取。
- Redis 不可用时保留本地缓存和回源；不保存凭据正文、权限结论、会话授权或唯一任务事实。
