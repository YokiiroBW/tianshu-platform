## 交给协调者的实际 App PG 检查入口

本号运行产物 `.runtime/ts296_fallback_app_smoke.py`，SHA256 `7943e7ce27c180c14c030d712323230e67428b91c2d3529c82fab42b2fdf80b0`，只静态检查，未连接 PG。此文件不在 wheel/Git 产品树，协调者需单独复制到隔离检查容器。

在 TS294 隔离原生 PG 测试准备好“完整旧 Platform 已 active → bootstrap 加 plugins → 新宿主写入至少一条合成 plugin_state”后，关闭新宿主，以同一个数据/binding 与合成设置、凭据挂载启动本号 fallback 镜像，再执行：

```sh
python -I /tmp/ts296_fallback_app_smoke.py --settings /etc/tianshu/settings-smoke.json
```

程序先用原只读端口读取全部 9 个插件表的行数/摘要，再调用真实 `Platform(settings)`，不手工重写登记步骤，也不 monkeypatch。它要求实际 App handles 与原 binding 完全一致且含 plugins、装配后仍 active、所有插件行原样保持、没有导入 SDK/PluginManager；最后 `app.close()`。输出只有逻辑源名、行数/摘要和装配结果。设置必须来自完整旧 App 形成的隔离 active binding，不能用 TS294 的 16 个 `existing_N` 人工源代替，否则真实 App 的原装配源集合不相符。该入口会执行正常 App 初始化，不能当作生产只读 probe；不启动 HTTP/Media/业务循环。

辅助本地运行产物：`ts296_local_checks.py` SHA256 `1f9449d6f200215b0545240f29fc0654f7b8b5cd949df8df8b6e79c5fb7d30ea`；`ts296_package_check.py` SHA256 `0accb31a251de41a752cb9b827632e1553218cbaded89b9a86d3dca4ad9bb686`。

## 回退边界

本候选只作为协调者验证后的兼容回退镜像，不替代正常 TS294 发布路径。使用迁后相同 PG/binding、storage0.1.3 和匹配的 context/history1.1 合同；不得删 plugins binding、恢复旧 23 源快照或覆盖之后写入。插件执行/页面在本旧版候选中不可用，但插件 PG 数据、Vault key 和机械盘包/cache 必须保留，供恢复 TS294 后继续使用。

保留现有数据、配置和媒体挂载。插件包拟用既有机械盘 `/var/lib/tianshu/platform.media-maintenance/plugins`；产品已审的维护/Retention 清理没有扫描该兄弟子目录，但旧冷备把此挂载列为 excluded_external_data，协调者需另行封存该目录并与 PG、binding、key 配对验证恢复。此路径判断与 TS294 主候选无进一步代码变更。
