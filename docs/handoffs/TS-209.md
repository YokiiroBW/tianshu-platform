## 修改与复用

`useControlRequest` 复用已有 `app/requestId.ts`，使用 LAN HTTP 可用的 Web Crypto `getRandomValues` 生成 UUID v4，覆盖 action、plan 和 execute 的共同发送路径。编号准备放入已有 `try/finally`，准备失败没有待恢复回执，提交锁会释放，并明确提示请求尚未发出。部署计划只在请求准备成功后标记已提交，失败时仍可重试，不增加确认步骤。

真实丢响应回归发现另一处直接相关问题：原发送响应丢失时，操作经只读查询完成后会清空 pending/query；空候选与空 pending 的编号都为 undefined，错误匹配导致已保存的 completed 结果消失。现在只有 pending 存在时才匹配候选，恢复后的完成结果保留；原编号持久恢复规则不变。

`StackDetail` 显式允许 `stack: null`。`StackInspector` 保留该响应中的 observation 和 refresh，按未结案的 queued/running 显示后台读取，已结案失败显示原因和原刷新入口；缺少栈详情时不显示可执行动作或部署表单。`compose_reference_outside_stack` 补充中文说明。已选择列表记录只在 node_id 与 stack_id 一致时提供名称和维护提示；详情还核对节点、栈及 refresh 的目标身份，切换目标不继承旧详情、错误或维护归属。可编辑部署面板只接受已经读到栈的详情类型。
