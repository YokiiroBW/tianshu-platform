# 网页角色占位选项修复

本轮仅完成 Platform 本地修复、验证与提交。基线为 `870e6fa958b7a8892a1273b6d87535ab4a02b025`，分支为 `codex/comfy-deep-20261005`；未推送、部署或修改生产配置与账本。

## 根因与改动

安装模板登记的 `actor:household` 同时进入生活读者目录、网页对话会话和记忆默认角色投影。没有角色管理记录时它仍会成为第一个选项，记忆目录还把此类静态登记显示为“默认角色”。技能页另有角色列表请求量 100 超过现有读者契约上限 50 的问题。

- 在既有 `role_runtime` 归属处统一判断：仅隐藏 ID 确为 `actor:household` 且尚无用户采用记录的安装占位。其他静态登记、ASCII ID、没有名称的真实角色及已采用的 `household` 均保留。
- 网页对话、生活／日记／图片、小屋、人物与用户档案、记忆、技能和 BOT 配置选择目录复用这一规则。记忆默认值从可见目录选择；没有角色则为空，兼容请求也不会使用占位 actor 读取业务。
- 生活列表若第一页仅含唯一占位且还有游标，保留原分页语义并前进一次，避免把后续真实角色误判为空；不增加通用循环读取。
- 空目录选择器保持空白；过往浏览器存下的占位偏好不会恢复成业务 actor。记忆页已经选中的真实角色后来撤权时，保留原有“已不在授权列表”安全状态，不悄悄切换人物。
- 技能目录请求限制改为 50，沿用已有分页。真实人格文档目录及角色采用目录不注入这个默认 actor，未过滤其实际文档，也未处理普通输入 placeholder 或空态说明。

源授权、已存在连接事实、角色账本和身份 ID 均未删除或改写；没有迁移、权限变化或新的门禁。
