# TS-149：音视频策略与真实兼容复用

目标：吸收 bili-sync 的质量范围、编码偏好及特殊流选择能力，并让下载、缓存与入库来源遵守相同策略，保留原 quality 行为。

基线：`c886c22d5949bbcb51d5cd0173b68909d5aa61f8`。分支：`codex/ts-149-media-policy`；本交接与实现为同一提交，精确交付 SHA 由协调消息记录。状态为本地已验证、待协调集成。

## 实现

- `config.quality()` 保留三必填键，新增可选 `stream_options`；空/全默认归一化省略，高级对象补全默认。精确字段、视频/音频逻辑排序、回退规则已同步父级与 TS-150，见 [流策略](../platform/media-stream-policy.md)。
- `stream_policy.py` 唯一拥有范围/编码/特殊流规则，供格式过滤、实际 format ID 选择、真实输出与所有复用入口使用。音频顺序明确为 30216/30232/30280/30250/30251；HDR/DV 独立开关。
- 下载证据来自实际 yt-dlp 选中流与 ffprobe，保存于现有下载/来源对象；不将请求策略作为文件证据。严格校验实际 codec 与特殊流；多音轨/视频逐条遵守排除。缺少当前约束必需证据的来源不命中，视频范围单独设置时仍可复用已有实际 QN。
- 原 BV/CID/QN 跨进程锁、CAS fencing、私有输入硬链接与取消语义继续使用。不同有效 SHA 的同 QN 来源使用 schema 2 `documents/download_variant` 保存，未迁移数据库。入库来源保存实际证据，回收不误删其他 codec/封装变体；内容存储仍按 SHA 硬链接。
- MP4/FLAC 兼容性通过 yt-dlp `mp4/mkv` 合法封装解决，不有损转码。多 P 混合容器只对必要的本任务私有 MP4 输入做 `-map 0 -c copy`→MKV，保留原缓存/成品 inode 和字节；新输入 prepared→ready、实际 SHA/探针/NFO/回执一致，后续复用成品实际 MKV。发布 media-package/v1 合同保持原单扩展要求。

## 实际验证

固定 Python 环境为共同 integration venv，固定 yt-dlp 2026.08.19；设置 `TS012_CONTRACT_DIR` 为 TS-141 隔离合同，FFmpeg/ffprobe 为本地 9.0.2，测试均使用临时合成媒体、临时 SQLite 与 loopback HTTP。

- 核心 57 项：stream policy 10、engine 15、download cache 16、imports 16。56 项通过，1 项因本 Windows 主机不能创建目录 symlink 条件跳过。新增 imports 用例首次因夹具 quality 使用字符串而失败，改为协议要求的整数后该项补跑通过；生产逻辑未因此修改。
- 既有 standalone 23 项通过；hardlinks 与 import-relocation 合计 30 项，29 通过、1 项因 Windows 无 Linux `/tmp`↔`/dev/shm` 跨设备环境跳过。合计 110 个不同测试，108 通过、2 条件跳过。
- 真实固定 yt-dlp merger + FFmpeg 合并 H.264/FLAC→MKV，ffprobe 实测仍为 H.264/FLAC；真实 HTTP/FFmpeg 两 P（AAC+FLAC）发布、私有 MP4 无损封装、旧 inode/bytes 保留、新 SHA/音轨/profile 保留、全部任务私有输入回收、重启后来源复用，均通过。
- 实际 SQLite/文件/独立进程验证同策略下载一次；不同 codec 不错误命中，切换回来可复用旧有效变体，偏好顺序变化不强迫重新下载；已核验成品的 SHA 硬链接回归通过。
- 受改动 Python 文件 `ruff format` / `ruff check`、完整 diff 阅读及 `git diff --check` 通过。后端改动未运行无关前端/全仓套件。

## 边界与下一步

本任务未使用真实账号、下载真实 B 站媒体、操作 NAS、执行生产迁移或部署。父级只读样本结果不作为本任务完整下载验证；Linux 镜像的 FFmpeg 5.1、真实 Dolby/Hi-Res 完整媒体和 Emby 验收由协调者继续。

旧来源缺少必需证据时会尝试其他来源或重新取流，不猜音频 ID。多 P 无损统一导致 SHA 不同的原缓存作为有效其他封装保留；不以新 MKV 的回执删除未由相同 SHA 成品承接的旧缓存。前端 TS-150 与共享 runtime/manifest/合同由父级串行集成，本任务没有并写。除本任务范围外未改公共依赖、迁移、发布合同和其他项目。
