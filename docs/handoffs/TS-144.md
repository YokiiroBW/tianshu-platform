## 入口与操作次序

受信同步入口 `ImportRelocation(media)`，异步调用通过现有 `media.local`。无新增 HTTP、应用装配、配置、数据库表或版本迁移。

```python
from services.platform.media.import_relocation import ImportRelocation
from services.platform.media.imports import item_id

# exact_mapping 由协调者的已核验文件整理计划提供；不是目录扫描猜出的身份。
raw_plan = {
    "schema_version": 1,
    "migration_id": "legacy-bilibili-source-layout-20261015",
    "root_id": "legacy-bilibili",
    "old_directory": "/media/observe/emby-video/短视频/manual/bilibili",
    "new_directory": "/media/Bilibili",
    "entries": [
        {
            "old_relative_path": old_relative,
            "new_relative_path": new_relative,
            "expected_record": media.repo.get(
                "media_import", item_id("legacy-bilibili", old_relative)
            ),
        }
        for old_relative, new_relative in exact_mapping
    ],
}
maintenance = ImportRelocation(media)
prepared = await media.local(maintenance.prepare, raw_plan)
validated = await media.local(maintenance.validate, raw_plan["migration_id"])
receipt = await media.local(maintenance.commit, raw_plan["migration_id"])
```

`raw_plan` 和每条映射是封闭字段，`expected_record` 必须是完整原登记记录（含 revision）。entries 必须精确覆盖该 root_id、old_directory 的全部原记录，遗漏、额外新增或改变记录均冲突拒绝。输入顺序统一按旧相对路径排序。prepare 支持同 root_id 配置仍指旧根或已经指新根；commit 必须已配置为新根，可在重新启动并加载新配置后执行。

prepare 只在实际验证全部文件后，向原 documents 写 `kind=import_relocation_plan,id=migration_id`；validate 重读实际文件和记录；commit 内部重新 validate，再通过 `Repository.import_relocate` 一个事务更新全部记录、当前可复用来源与 `kind=import_relocation,id=migration_id` 回执。复用原 `.imports/digest(root_id)` 操作锁，和 Imports.reconcile 互斥。异步取消调用也不会让仍执行同步文件检查的线程提前释放锁。

## 身份与证据

- 旧视频的实际 dev/ino/size/mtime 必须匹配原 observation，新旧路径必须指向实际普通文件，复用 imported_path 拒绝软链接、junction 和越界路径。
- 新旧 dev/ino/size/mtime 相同，使用硬链接证明，不重读数百 GB 视频；准备和提交间同时比较 ctime 的 observation，文件工作前后也检查完整 observation。
- 不同文件对象（包括同卷复制）实读双方 SHA256，确认大小、内容一致；若原登记已有 SHA256，还必须一致。复制生成的 SHA256 属迁移证明，不填入 unknown/invalid 的质量证据。提交后复制路径的重复执行会实读目标摘要，旧文件可已由协调者另行清理。
- 新 ID 仍为 `digest({root_id, relative_path: new_relative_path})`；根变更但相对路径不变也支持。记录 revision 连续为原 revision+1，同步 media_source 的 import_record_id、import_record_revision、路径、entry 与 evidence_digest。
- 完整保留 BV/CID/分 P、actual_quality、state/code、缺失证据、原测流和时长、quality_evidence/source_digest。只更新当前路径、observation、identity_evidence.relative_path 与按新路径重建的既有 manifest evidence_digest，并加入 relocation 证据。原记录、原摘要和证明保存在计划/回执，不把 invalid 或 unknown 变 verified。
- verified 来源仍走既有 Imports.source → Retention → DownloadCache，继续实际 hash 校验和 pin。失效状态的旧 stale 来源引用删除并留在迁移回执；verified 的来源字段或修订不一致则拒绝整个事务。
- 同 migration_id、同输入重复执行不产生新修订；改变输入拒绝。重复 commit 同样核验新记录、当前来源及目标文件，已变化状态不冒称重放成功。
