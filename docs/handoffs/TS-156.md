# TS-156 自动音乐解锁

基线为已部署 Platform `73fd5941e998463c11e9115eb84300fbf07b34cf`，独立分支
`codex/ts-156-music-unlock`。分配器因历史协调检出存在修改拒绝，精确基线隔离创建工作树，保留其他任务原改动。

下载与本地导入复用 `music/decoding.py` 和内置 Unlock Music CLI。按实际文件头、
QMC 尾部、来源文件名/格式识别加密音频，普通音频直接进入既有完整解码校验。
解锁后仍校验时长、实际音质和标签前后 PCM 身份，通过同一 Catalog/AudioStorage
登记、去重、原子发布及歌单引用；不引入另一套数据库或队列。

增加 OGG/Vorbis、Opus 原编码校验和标签/封面写入，避免 QMC 解出 OGG 后无法归档。
导入按实际音质复用已归档同曲，修复“best”策略让相同原件再存一份的路径。
任务、数据库文件回执及来源 JSON 保存解锁状态、格式、工具版本和输入摘要；
失败换源记录仅有平台、歌曲ID和原因，不保存凭据、签名URL或密钥。

缺少客户端密钥、版本不支持、解锁失败分别显示；候选失败后尝试下一获准来源。
本地原件保留，下载失败暂存遵循既有回收机制。NCM/QMC/KGM 已有算法沿用
固定上游；QMC STag/MusicEx、KGM v5/KGG 外部客户端密钥仍未接入。
汽水继续按用户指示跳过。解锁不改变账号对歌曲的下载权限。

Windows 相关下载/曲库/HTTP 48 项中 47 通过、1 POSIX 权限条件跳过；
新增真实解码链路 6 项通过，涉及 NCM 自动下载、导入反向复用、QMC OGG、
普通 Opus、缺钥换源、取消保留。导入质量调整后曲库+新增共22项重新通过，
含同一个 POSIX 跳过。网页桌面/手机18项通过；类型和生产构建通过。
Go、最终审查、Linux候选及NAS发布证据由协调记录续记，不能将隔离合成音频
验证当作本人商业歌曲的加密原件实测。
